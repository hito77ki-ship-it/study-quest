仕様を入出力に分けてから、手順を書いて試す

図書館が「4人以上で予約したグループの人数を合計したい」と依頼したとします。入力は各グループの人数の一覧、出力は条件に合う人数の合計です。「4人ちょうどを含むか」「合う予約がなければ何を返すか」を先に決めると、コードを書いた後の確認がしやすくなります。

人が言語で書いた命令の並びをソースコードといいます。言語の書き方に反する構文エラーと、処理は動いても仕様と結果が違う不具合を分けます。後者を調べるときも、入力と値の変化を記録して原因を絞る作業はデバッグです。仕様が4人以上なのに「4より大きい」と書くと、4人ちょうどが漏れます。

プログラム言語と、コードを処理する仕組みを分ける

CPUが解釈する命令を機械語といい、命令に記号を使うアセンブリ言語は低水準言語の一つです。C、Java、Python、JavaScriptなどの高水準言語は、人が目的や処理を記述しやすい形を提供します。例えばCは組込みなどにも使われ、Javaでは中間表現を仮想マシンで実行する構成が一般的です。Pythonは集計や自動化などにも使われ、JavaScriptはブラウザ上のページ操作に使えます。

例えばC++はネイティブアプリケーションなど、C#は.NET上の開発、Fortranは数値計算、Rは統計分析、COBOLは事務処理、PHPやRubyはWeb開発で使われることがあります。用途には重なりがあり、チームで保守できるか、必要な環境やライブラリがあるかでも選びます。

コーディング標準は、名前の付け方や字下げなど、チームで読みやすく保つための取り決めです。ライブラリは再利用できる機能をまとめたもの。例えば日付の処理を呼び出せます。APIは機能を使うための接点や約束で、どんな入力を渡すか、何が返るかなどを定めます。Webを介して機能を使う窓口はWeb APIの一例です。

全体を進めるメインルーチンと、人数の集計などの仕事を分けたサブルーチンを考えると、処理を役割ごとに整理できます。機能をモジュールとして分ければ、例えば集計の修正箇所を絞れます。ローコードやノーコードでは画面操作などで機能を組み立てますが、入出力と境界値の確認は同じです。

HTML、CSS、XML、JSONは、どこで使うかを見分ける

HTMLで <h2>予約状況</h2> と書くと、文字列が見出しだと示せます。CSSでその見出しの余白や色を指定し、JavaScriptでボタンを押したときの処理を組めます。タグ名・要素の入れ子・閉じ方などは、各形式の規則を確認します。

他のシステムに予約情報を渡すなら、XMLでは <予約><人数>4</人数></予約> のようなタグを定義できます。JSONでは {"部屋":"A","人数":4} のように名前と値の組で表せます。JSONはデータ交換形式で、HTMLやXMLのように開始・終了タグで項目を囲みません。SGMLは文書の構造を記述するための規格で、XMLはそこから機能を絞って作られました。

擬似言語は、条件を調べた行と値を更新した行を区別する

擬似言語は、手順に集中して読むための表し方です。試験では問題文に個別の注記があれば、そちらを使います。注釈は読み手への説明で、実行する命令とは区別します。以下の自作例では配列の要素番号は1から始まり、引数 人数 の要素数は4とします。

○整数型: 対象人数の合計(整数型の配列: 人数)
  整数型: 合計, i
  合計 ← 0
  for (i を 1 から 4 まで 1 ずつ増やす)
    if (人数[i] が 4 以上)
      合計 ← 合計 + 人数[i]
    endif
  endfor
  return 合計

引数は呼出し側から渡す値、戻り値は return で呼出し側へ返す結果です。この関数を {2, 5, 0, 4} で呼ぶと9を返します。戻り値を使う関数と、受付の記録など動作をまとめた手続を区別して読みます。

← は代入、＝ は等しいかの比較です。mod は割った余りを求めます。論理型の値は true または false です。IPAの記述形式では、二項演算の範囲で乗除・剰余、加減、比較、and、or の順に優先されます。式が長ければ、括弧のまとまりを先に見ます。

if、elseif、else が一つにつながっているときは、上から条件を確認し、最初に当てはまった処理だけを行います。独立した二つの if では、両方の処理が実行されることがあります。

ループは「最初の判定」と「最後の更新」を確かめる

配列 {{2, 5}, {0, 4}} を「行＝階、列＝部屋」と決め、番号を1から始めるなら、人数[2, 1] は2行目の1列目で0です。配列を読む範囲は「1から最後まで」と決め、要素番号の開始位置が異なる設問では条件を書き直します。

実際に紙に書くなら「いま見ている要素番号」「条件の結果」「更新後の値」を同じ行に置きます。何度も値が更新される問題は基本情報の変数トレースで続けて練習できます。

例題8問と解説

Study Quest編集部の自作問題です。先に答えを考えてから、各問の「解答と解説」を開いてください。

第1問　仕様の境界を試す

4人以上を集計する仕様です。4人が漏れる不具合を直接確かめる入力はどれですか。

  1. 4人の1件
  2. 5人の1件
  3. 0人の1件
  4. 10人の1件
第1問の解答と解説

ア　4人の1件

比較条件を「4より大きい」と誤っても5人や10人は通ります。4人を使うと、本来は足すべき境界値が漏れるか確認できます。

第2問　言語プロセッサ

人が書いたコードを実行前に一括して別の形に変換します。この方式の説明に最も近いのはどれですか。

  1. タグ付け
  2. リンク先の読込み
  3. コンパイル
  4. コードの字下げ
第2問の解答と解説

ウ　コンパイル

実行前にソースを翻訳するのはコンパイルの考え方です。インタプリタの典型例では解釈しながら実行します。

第3問　形式の役割

予約ページで、見出しの色を変えたい。見出しの文字や予約データはそのままにする場合、主に変更するのはどれですか。

  1. JSONの人数
  2. CSSの指定
  3. XMLのタグ名
  4. 擬似言語の戻り値
第3問の解答と解説

イ　CSSの指定

色は表示の指定なのでCSSが担当します。HTMLの見出しは構造、JSONやXMLの予約情報はデータです。

第4問　要素番号を追う

要素番号が1から始まる二次元配列 {{7, 8}, {3, 6}} があります。値[2, 1] はいくつですか。

  1. 7
  2. 8
  3. 6
  4. 3
第4問の解答と解説

エ　3

最初に2行目の {3, 6} を選び、次にその1列目を選ぶので3です。行と列を逆にすると別の値を読んでしまいます。

第5問　集計の途中を確かめる

本文の 対象人数の合計 に {6, 1, 4, 2} を渡します。3番目を処理した直後の合計はどれですか。

  1. 6
  2. 7
  3. 10
  4. 11
第5問の解答と解説

ウ　10

最初の6は足し、2番目の1は足しません。3番目の4は条件に含まれ、6＋4＝10です。

第6問　最初に当てはまる条件

人数が7です。1つの if の中で、先に「5以上なら通常室」、続く elseif で「7以上なら大部屋」と判定します。どの処理が行われますか。

  1. 通常室だけ
  2. 大部屋だけ
  3. 通常室と大部屋の両方
  4. どちらも行わない
第6問の解答と解説

ア　通常室だけ

7は最初の「5以上」を満たすので、そこで分岐が決まります。大部屋を先に判定するなら、条件の順序を入れ替えます。

第7問　最初から条件が偽

カウンタの初期値は0です。処理はカウンタを1増やすこと、継続条件は「カウンタが0未満」です。前判定と後判定で処理はそれぞれ何回ですか。

  1. 前判定1回、後判定0回
  2. 前判定0回、後判定1回
  3. 両方0回
  4. 両方1回
第7問の解答と解説

イ　前判定0回、後判定1回

前判定では初期値0の時点で偽です。後判定では先に1増やしてから判定し、1は0未満でないのでそこで止まります。

第8問　余りで処理を選ぶ

(番号 mod 2 ＝ 0) and (番号 ≥ 4) を満たす番号はどれですか。

  1. 2
  2. 3
  3. 5
  4. 6
第8問の解答と解説

エ　6

2で割り切れて、かつ4以上の値です。2は割り切れますが4未満、5は4以上ですが余りが1です。6は両方を満たします。
