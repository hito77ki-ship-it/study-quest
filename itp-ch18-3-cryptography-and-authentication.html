ITパスポート 18-3 後編 暗号と認証

文化祭の引継ぎを例に、共通鍵と公開鍵、デジタル署名と証明書、多要素・生体認証を図解と例題で学びます。

読む人を限るには、どの鍵で何をする？

文化祭の担当者が、受付の引継ぎファイルを送るとします。読める形のデータを平文と呼び、鍵を使って読めない形に変えるのが暗号化、戻すのが復号です。暗号の強さは鍵の長さだけで決まるわけではなく、方式・実装・鍵の保管にも左右されます。

公開鍵の技術を使って共通鍵を安全に共有したり導出したりし、本文を共通鍵暗号で保護する組合せがハイブリッド暗号方式です。例えばTLS 1.3では、証明書による認証を行う接続で、公開鍵技術による鍵共有と、導出した鍵による対称暗号を組み合わせます。ディスク暗号化は主に保存媒体を、ファイル暗号化は対象のファイルを守ります。

変更されていないか、誰の鍵かを確かめる

ハッシュ関数は、データを一定長の要約値に変換します。暗号学的ハッシュでは、要約値から元のデータを求めることや、同じ要約値になる異なるデータを見つけることが困難になるよう設計します。署名方式ではハッシュを利用するものがあり、単にハッシュ値を公開することと、秘密鍵で署名することでは証明できる内容が異なります。

何を確かめたいかで選ぶ
目的仕組み見分ける点
内容を読める相手を絞る暗号化公開鍵暗号の例では受信者の鍵を使う。
署名した鍵と改ざんの有無を確かめるデジタル署名署名者の秘密鍵で作り、公開鍵で検証。
その時刻までに存在したことを確かめるタイムスタンプ信頼できる時刻認証で、後のデータとの一致も検証できる。
公開鍵と相手の対応を確かめるデジタル証明書認証局の署名と証明書の有効性などを検証。

認証局（CA）が証明書を発行します。CRLは有効期間内でも失効した証明書を確認するための一覧です。サーバ証明書は通信先のサーバの確認に、クライアント証明書は接続する端末や利用者などの確認に使われます。

認証の要素を分け、生体認証の誤りを数える

認証は誰であるかなどを確かめ、認可は認証後などに許された操作を判断します。受付係としてログインできても、管理者だけが持つ名簿の削除権限まで付くわけではありません。詳しくは「認証と認可の違い」で扱っています。

利用者を確認する方法を区別する
方法使われ方
ワンタイムパスワード・SMS認証一回限りのコードなどで確認する。短時間でも偽サイトに渡さない。
パスキーサイトとひも付いた公開鍵方式で確認する。端末側でPINや生体を使うことがある。
シングルサインオン一度の認証で、連携した複数のサービスに入れるようにする。
リスクベース認証普段と違う端末など、状況に応じて追加確認を求める。
ニーモニック・パターン認証覚えやすい手掛かりや、画面上の操作パターンなどを使う。
CAPTCHA自動操作と人の操作を区別するために使う。特定の本人かは別途確認する。
EMV 3-Dセキュアオンラインのカード決済時に、カード利用者の確認を支援する仕組み。

生体認証では指紋、顔、声紋、静脈、虹彩、網膜などの特徴を使います。虹彩は目の色の付いた部分の模様、網膜は目の奥の構造に着目します。一般に照合基準を厳しくすると、他人受入れは減る方向ですが、本人拒否は増える方向に動きます。どちらの誤りを避けたいかと、代替の確認手順を考えます。

例題10問と解説

Study Quest編集部の自作問題です。先に答えを考えてから、各問の「解答と解説」を開いてください。

第1問　同じ鍵で戻す

受け取った名簿を、送信側が暗号化に用いた鍵と同じ鍵で復号します。何ですか。

  1. 公開鍵暗号
  2. 共通鍵暗号
  3. ハッシュ関数
  4. タイムスタンプ
第1問の解答と解説

イ　共通鍵暗号

暗号化と復号で同じ秘密の鍵を使うため、共通鍵暗号です。

第2問　受信者だけが読める

公開鍵暗号の例で、担当Bだけが読めるよう暗号化します。どの鍵で暗号化しますか。

  1. 送信者の公開鍵
  2. 送信者の秘密鍵
  3. Bの公開鍵
  4. Bの秘密鍵
第2問の解答と解説

ウ　Bの公開鍵

Bの公開鍵で暗号化し、対応する秘密鍵を持つBが復号します。

第3問　署名を検証する

担当Aが自分の秘密鍵でPDFに署名しました。受け取った側はどの鍵で検証しますか。

  1. Aの公開鍵
  2. Aの秘密鍵
  3. 受信者の秘密鍵
  4. 共通鍵
第3問の解答と解説

ア　Aの公開鍵

対応するAの公開鍵で署名を検証します。公開鍵が本当にAのものかも確認します。

第4問　何時までに存在したか

書類が受付締切までに存在したことを後から確かめたいとき、何を使いますか。

  1. WAF
  2. MDM
  3. ファイル圧縮
  4. タイムスタンプ
第4問の解答と解説

エ　タイムスタンプ

信頼できる時刻認証を使い、その時点で対象データが存在したことを示す用途です。

第5問　まだ有効期限内だが失効

有効期限内でも失効した証明書を一覧で確認するものはどれですか。

  1. SSID
  2. CRL
  3. CSVの名簿
  4. PSK
第5問の解答と解説

イ　CRL

CRLは失効した証明書の一覧です。有効期限だけでは失効を判定できません。

第6問　異なる種類を選ぶ

知識と所持を組み合わせるものはどれですか。

  1. パスワードとPIN
  2. 顔と指紋
  3. パスワードと登録済みのセキュリティキー
  4. 二種類のパスワード
第6問の解答と解説

ウ　パスワードと登録済みのセキュリティキー

パスワードは知識、物理セキュリティキーは所持です。二つの異なる種類を使います。

第7問　不審な端末だけ追加確認

初めての端末からログインした場合だけ追加確認を求めます。どの考え方ですか。

  1. リスクベース認証
  2. 単なる認可
  3. WORM
  4. デジタルフォレンジックス
第7問の解答と解説

ア　リスクベース認証

端末や状況からリスクを見積もり、確認を強める方法です。

第8問　試行数を分けて計算

本人の200回で4回を誤拒否、別人の500回で1回を誤受入れしました。本人拒否率と他人受入率はいくつですか。

  1. 0.2%と2%
  2. 0.8%と0.5%
  3. 4%と1%
  4. 2%と0.2%
第8問の解答と解説

エ　2%と0.2%

本人拒否率は4÷200×100＝2%。他人受入率は1÷500×100＝0.2%です。

第9問　照合を厳しくする

ほかの条件は同じで生体認証の照合基準を厳しくすると、一般にどうなりますか。

  1. どちらの誤りも必ず減る
  2. 本人拒否が増え、他人受入れが減る方向
  3. 本人拒否が減り、他人受入れが増える方向
  4. 両方とも必ず0になる
第9問の解答と解説

イ　本人拒否が増え、他人受入れが減る方向

一致とみなす条件を厳しくすると他人を通しにくい反面、本人も拒否されやすくなります。

第10問　ログインと権限

受付係と確認できた後、名簿を閲覧できるが削除はできないようにします。削除可否の判断は何ですか。

  1. 暗号化
  2. ハッシュ
  3. 認可
  4. 時刻認証
第10問の解答と解説

ウ　認可

本人確認は認証、許される操作かの判断は認可です。
