システム化計画は、対象・順序・費用・担当を決める

前編の方針をもとに、まず大学図書館の自習席を対象にします。システム化構想では、空席が窓口ごとに分かれている問題と、予約情報を共有する方向を整理します。システム化計画では、対象フロア、着手順、概算費用、担当者、期待する効果とリスクを具体化します。例では1フロアで試し、二重予約が防げるか確かめてから対象を広げます。

ソフトウェアのライフサイクルは企画から開発、運用、保守、廃棄までを含みます。SLCPはそれらの作業を共通に捉える考え方です。受付開始直前に一斉切替すると混乱しやすいため、試行期間と、障害時に紙へ戻す判断を計画に含めます。

費用は初期費用に加え、利用料、保守、研修、移行などを同じ期間で比較します。次の架空例では案Aの初期費用が大きいものの、3年合計は案Bより3万円少なくなります。

要件定義は、希望を確認できる条件に変える

利用者の「もっと予約を取りやすく」、職員の「重複予約をなくしたい」という希望を調べます。業務要件では、利用者、手順、担当、ルールを定義します。機能要件では、システムが何をできるようにするか、非機能要件では、性能、可用性、セキュリティ、運用性などの条件を具体化します。

例えば「混んでも速い」だけでは、受入れ時の判断がそろいません。「同時30人が予約操作をした場合、応答の95%が2秒以内」と書き、対象の操作、測定環境、試行回数を合意します。業務ルールの「1日1枠」に対し、機能では「同じ学生が同日の2枠目を申し込むと拒否して案内を表示する」と決められます。どの条件もこの設例の値です。

聞いた要望を、確かめられる要件にする
利用者の声条件と確認方法
予約が取れたか知りたい確定後に席番号と時間を表示する。登録された予約と一致するか照合。
他人の予約情報を守りたい一般の学生は自分の予約だけ閲覧できる。別アカウントでアクセスを試す。
通信が切れても窓口を回したい手作業へ切り替える責任者、重複防止、復旧後の照合手順を決める。

調達は、情報を集めてから提案を比較する

どんなサービスがあるか分からない段階で、発注側が候補会社に提供範囲や導入実績を聞くのがRFI（情報提供依頼）です。方針や要求が具体化したら、発注側がRFP（提案依頼書）を作り、同じ条件に対する具体案を求めます。候補会社から戻る提案書には構成や実施方法、見積書には費用や条件が記されます。

RFQ（見積依頼）は、調達する対象や条件が定まっていて、金額などの提示を求める場面です。RFPでは解決方法や体制も比較したいという目的があります。調達方式によって進め方は変わりますが、この例では、提案を見る前に必須条件と評価の観点を決めます。

例えば「同じ席に二人が同時に申し込んでも、確定は一件」が必須なら、費用が安くても満たさない提案は選定対象から外します。必須を満たした案は同じ期間の費用、移行方法、問い合わせ対応、データを取り出せるかなどを比べます。グリーン調達では、機器の消費電力など環境面の条件も検討します。

受入れ・検収で、契約した条件を実際に確かめる

導入する案が決まったら、作業範囲、費用、納品物、検収条件などを契約で合意します。納品されたら、受入れの確認を行い、要求どおりかを検収で判定します。試験は「画面が開くか」だけでなく、同時予約、性能、権限、障害時の案内など約束した条件ごとに記録します。

同じ席への同時予約で両方が確定したら、条件を満たしていません。再現した操作、期待した結果、実際の結果を残し、合意した方法で修正と再試験を進めます。引き渡すのは画面だけでなく、職員向けの手順、問い合わせ窓口、必要なデータの出力方法も含めて考えます。

解説つきの自作例題6問

まず自分で選び、解答を開いて、判断に使った条件を確かめます。

第1問　1フロアから順に導入する

予約システムを最初に1フロアで導入し、費用・担当・次に広げる時期を整理します。主にどの段階ですか。

  1. 納品後の検収
  2. システム化計画
  3. 運用開始後の保守
  4. RFIへの回答
第1問の解答と解説

イ　システム化計画

対象、導入順、概算費用、体制を決めるのはシステム化計画です。検収では契約した条件が実際に満たされたかを確かめます。

第2問　使い続ける費用を比べる

案Aは初期10万円と年4万円、案Bは初期4万円と年7万円です。他の条件が同じ場合、3年の合計はどうなりますか。

  1. 案Aが22万円、案Bが25万円で案Aが3万円少ない
  2. 案Aが14万円、案Bが11万円で案Bが3万円少ない
  3. 案Aが22万円、案Bが25万円で案Bが3万円少ない
  4. 初期費用の差だけを比べればよい
第2問の解答と解説

ア　案Aが22万円、案Bが25万円で案Aが3万円少ない

案Aは10＋4×3＝22万円、案Bは4＋7×3＝25万円です。運用期間をそろえると初期費用とは比較結果が変わります。

第3問　予約画面の速さを約束する

「同時30人で予約操作を行い、応答の95%が2秒以内」という条件は、どの要件ですか。

  1. 利用者の範囲を定める業務要件
  2. 予約を取り消す機能要件
  3. 応答時間を定める非機能要件
  4. 候補会社に送るRFI
第3問の解答と解説

ウ　応答時間を定める非機能要件

予約できることは機能、どの条件でどの速さを求めるかは性能の非機能要件です。測定する環境もそろえます。

第4問　市場調査と提案依頼を区別する

候補会社から既存サービスの情報を集めた後、共通条件を示して具体的な導入案の提出を求めます。依頼文書の順番はどれですか。

  1. RFP、RFI
  2. 見積書、提案書
  3. 提案書、RFQ
  4. RFI、RFP
第4問の解答と解説

エ　RFI、RFP

情報を集めるためのRFIを行い、その情報も使って具体案を求めるRFPを作ります。提案書は候補会社が発注側へ提出します。

第5問　必須の条件を外さない

重複予約防止を必須としました。A社は最安ですが未対応、B社は対応しています。どう評価しますか。

  1. 価格だけを見てA社を選ぶ
  2. 必須条件に沿って評価し、B社の費用や運用も確認する
  3. 両社を同点にする
  4. 契約後まで重複予約について聞かない
第5問の解答と解説

イ　必須条件に沿って評価し、B社の費用や運用も確認する

必須条件と比較評価項目を分けます。必須に適合した案について、同じ条件で費用や運用を評価します。

第6問　納品された予約機能を確かめる

契約では同じ席に同時申請しても確定は1件としました。受入れ試験で2件とも確定したときに行うのはどれですか。

  1. 再現手順と期待・実際の結果を記録して修正と再試験を行う
  2. ページが表示されたので合格とする
  3. 見積書の価格だけ確認する
  4. 検収記録に期待した結果だけを書く
第6問の解答と解説

ア　再現手順と期待・実際の結果を記録して修正と再試験を行う

合意済みの条件に対する不一致を記録します。修正後も同じ手順で再試験すれば、条件を満たしたかを比較できます。
