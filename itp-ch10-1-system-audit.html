ITパスポート 10-1 システム監査と内部統制

図書館の予約を題材に、監査の独立性、証拠と調書、ウォークスルー、内部統制とITガバナンスを学びます。

運用している人と、独立して確かめる人を分ける

図書館の予約サービスが始まりました。窓口では予約の代理登録や取消を行い、学内IT部門ではシステムを保守します。システム監査では、その仕組みに関わるリスクを捉え、対策が適切に作られ運用されているかを、証拠に基づいて確かめます。例えば職員の異動後に権限が残っていないか、障害時の代替手順が使えるかを見ます。

業務監査は手続や業務の有効性など、財務諸表監査は財務諸表の適正な表示、システム監査は情報システムに関わる統制などが主な対象です。システム監査の対象には、企画・開発・運用・保守なども含まれ得ます。個別監査の範囲は、目的とリスクに応じて定めます。

システム監査基準は監査人の行為や監査手続の規範です。システム管理基準は情報システムを管理するための考え方を示し、監査で判断する尺度としても使えます。保証を目的とした監査では証拠を評価して結論を出し、助言を目的とする監査では合意した範囲で改善などを提案します。

一件の予約を追い、結論を証拠で支える

監査証拠には、権限変更の履歴、作業記録、関係者の説明などがあります。監査人は証拠が判断に適しているかを評価します。例えば「削除しました」という説明だけでなく、異動記録の日付と削除ログを照合します。

方法図書館での例
インタビュー担当者に、例外時の手順と実際の判断を聞く。
閲覧・観察権限表を読み、窓口で手順がどのように行われるかを見る。
ウォークスルー法予約1件を選び、申請、承認、記録、通知までの処理を資料と照合しながらたどる。
テストデータ法監査用の入力を処理し、期待どおりの結果が出るかを安全な条件で確かめる。

内部統制の目的と、それを支える六つの要素

内部統制は、組織の目的を達成するために日々の業務に組み込む仕組みです。例えば代理予約を承認制にし、誰が登録・取消したか記録します。経営者は整備・運用に責任を持ち、職員はそれぞれの業務で手続を実施します。

六つの基本的要素を学習室予約に当てはめる
要素図書館での例
統制環境責任者と役割を決め、例外の隠蔽を許さない方針を示す。
リスクの評価と対応無断取消の可能性と影響を見積もり、対策を決める。
統制活動申請する人と承認する人を分ける。
情報と伝達取消記録を担当者と責任者に共有する。
モニタリング取消記録を定期点検し、統制が機能しているかを見る。
ITへの対応職員権限を管理し、ログが適切に保存されるようにする。

IT全般統制は、アクセス権管理や変更管理など複数の業務を支える共通の仕組みです。IT業務処理統制は、予約の人数が範囲内かなど、特定の業務で入力や処理が正しく行われるための仕組みです。ITガバナンスは、組織の目的に沿ってIT利用の方向を示し監督する取組です。ITマネジメントでは、方針を実行し、結果を評価・報告します。不適切な運用が公になり、組織の信頼が損なわれる可能性はレピュテーションリスクです。

例題8問と解説

Study Quest編集部の自作問題です。先に答えを考えてから、各問の「解答と解説」を開いてください。

第1問　誰に点検を頼む？

学習室予約の運用を客観的に評価してもらう相手は誰が適切ですか。

  1. 仕組みの承認者本人
  2. 独立した監査担当者
  3. 設定を行った担当者本人
  4. 予約利用者の代表一人だけ
第1問の解答と解説

イ　独立した監査担当者

監査では、判断が監査対象の作業や利害に影響されないよう独立した立場を確保します。自己点検や利用者の意見も、別の目的では活用できます。

第2問　証拠を選ぶ

異動した職員の権限が期限内に解除されたかを確かめたい。最も直接的な組合せはどれですか。

  1. 画面の配色と申請書の紙質
  2. 今日の利用件数と来月の計画
  3. 異動記録と権限を削除した日時のログ
  4. 担当者の感想だけ
第2問の解答と解説

ウ　異動記録と権限を削除した日時のログ

対象と期限が分かる異動記録を、実際の権限削除の記録と照合します。必要なら現在の権限も再確認します。

第3問　業務の流れを理解する

取消申請を一件取り上げて、窓口の受付から台帳・通知までをたどります。使っている方法はどれですか。

  1. ウォークスルー法
  2. 負荷テスト
  3. ハウジング
  4. サービスレベル管理
第3問の解答と解説

ア　ウォークスルー法

処理の一連の流れを追跡します。負荷テストは大量の処理に耐えられるかを調べる試験です。

第4問　記録と報告の使い分け

どの記録を何件照合し、どの例外を見つけたかを監査の手続とともに残すものはどれですか。

  1. 予約カタログ
  2. システム要件定義書
  3. 見積書
  4. 監査調書
第4問の解答と解説

エ　監査調書

監査調書は実施した手続や結果を記録し、結論の裏づけになります。関係者には監査報告書で所見や結論を伝えます。

第5問　承認と実行を分ける

ある職員が代理取消を申請し、別の責任者だけが承認できるようにしました。内部統制の基本的要素では何の例ですか。

  1. 情報と伝達だけ
  2. 統制活動
  3. 統制環境だけ
  4. 資産の保全という目的そのもの
第5問の解答と解説

イ　統制活動

権限を分ける具体的な手続は統制活動です。資産の保全はこの仕組みが支え得る目的です。

第6問　IT統制の対象を選ぶ

複数の業務システムで共通の職員IDを使っています。異動時にその権限を一括で見直す手続はどれですか。

  1. 特定の予約人数のチェック
  2. デバッグ
  3. IT全般統制
  4. サービスカタログ
第6問の解答と解説

ウ　IT全般統制

複数の業務を支えるアクセス管理なのでIT全般統制です。予約の人数の妥当性をチェックする処理は、その業務の処理統制です。

第7問　指摘のあとに行うこと

監査報告のあと、図書館は異動翌日に権限を見直す手順を導入しました。監査側がその実施状況を再確認する活動はどれですか。

  1. 見積り
  2. プロジェクトの立ち上げ
  3. データの正規化
  4. フォローアップ
第7問の解答と解説

エ　フォローアップ

改善策を知らせてもらうだけでなく、実際に運用されているかを証拠で確認します。

第8問　経営と運用の役割

図書館の方針を決める会議で、利便性と個人情報保護を両立するIT利用の方向を定め、実施状況を監督します。中心になる概念は何ですか。

  1. ITガバナンス
  2. テストデータ法
  3. 需要管理
  4. ネットワーク設計
第8問の解答と解説

ア　ITガバナンス

組織の目的に合わせて方向を示し監督するのはガバナンスです。運用担当が方針に沿って手続を実行し報告するのはマネジメントです。
