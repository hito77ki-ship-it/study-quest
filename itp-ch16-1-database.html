ITパスポート 16-1 データベース

文化祭の注文表を題材に、DBMS、主キー・外部キー、正規化、選択・射影・結合を図解と例題で学びます。

模擬店の注文台帳で、DBMSの役割をつかむ

文化祭でレモネードとクッキーを売るとします。注文番号、商品、数量をためて検索できるようにしたデータの集まりがデータベースです。その台帳を、受付係と在庫係が安全に使えるように管理するソフトウェアがDBMSです。

注文と商品を表に分ける方式は関係データベースで、これを管理するDBMSがRDBMSです。データのつながりを親子の木で表す階層型、複数のつながりを持つ網型、データをオブジェクトとして扱う方式もあります。データモデルとは、こうしたデータと関連の表し方です。

レプリケーションは、別のサーバにもデータの複製を維持する仕組みです。障害時の切替えや読取りの分散に使えます。誤って消したデータまで複製先に反映されることがあるため、過去の時点に戻せるバックアップも別に考えます。

レシートを1行ずつ見て、主キーと外部キーを決める

表の横1行はレコード、縦1列はフィールドです。1行が「商品1種類」なのか「注文の明細1件」なのかを先に決めます。テーブルの列、データ型、キー、表同士の関係といった構造を定義したものをスキーマと呼びます。この例では商品IDを文字列、数量を正の整数にします。コード設計では、P01のように対象を一意に識別できる規則を決めます。

主キーは1行を一意に識別します。重複やNULLは許されません。NULLは値が未設定などであることを表し、空文字や0とは別です。注文明細表では注文IDだけだと同じ注文に複数行があるため、「注文ID＋行番号」を複合主キーにします。

外部キーは、別の表などの参照先と対応させるための制約です。この例の明細には商品IDが必須で、商品表にないP99を登録すると制約違反です。一方、P01が複数の明細に出るのは正常です。図のように実体と関連を表す図をE-R図と呼び、1対多のほか、1対1や多対多の関係も表せます。注文と商品の多対多は、注文明細表を間に置くと表せます。

この模擬店で用意する表
表1行の単位主キーと参照先
注文表注文1件注文ID
商品表商品1種類商品ID
注文明細表注文内の1明細注文IDと行番号。注文IDと商品IDは外部キー

正規化は、ある情報をどこに持つか整理し、更新時の食い違いなどを減らすための設計です。例えば注文行を全部消しても、商品表が独立していれば商品情報は残ります。販売時に合意した単価のように、現在の商品情報とは独立した履歴は明細に残します。

インデックスは本の索引のように、条件に合う行を探す手掛かりです。商品IDなどで繰り返し検索する場合に役立つことがあります。保存領域が必要で、登録・更新時に索引を保つコストも増えるため、よく使う検索を調べて選びます。

結合して商品名を出し、行と列を絞る

例えば「2個以上の明細を多い順に見たい」ときは、注文明細表と商品表を商品IDで結合します。次に数量が2以上の行を選択し、表示する注文ID・商品名・数量の列を射影します。

明細と商品を結合し、数量2以上で絞った結果
注文ID商品名数量
O102クッキー3
O101レモネード2

同じ操作をSQLで表すと下のようになります。SQLの文法と正規化の細かな段階は、参照したIPAシラバスの範囲では出題対象外です。SELECTの後ろは出す列、WHEREは残す行、と問題文に戻して読めば判断できます。

SELECT d.order_id, p.name, d.qty
FROM order_lines AS d
JOIN products AS p ON d.product_id = p.product_id
WHERE d.qty >= 2
ORDER BY d.qty DESC, d.order_id;
注文を「見る・まとめる・変える」操作
操作模擬店での使い方
並べ替え昇順なら数量の小さい順、降順なら大きい順。行の表示順が変わる。
集計数量を商品ごとに合計すると、レモネードは2＋1＝3個、クッキーも3個。明細数はそれぞれ2件と1件。
ビュー集計担当に必要な列を出す、問い合わせを定義した仮想的な表。
挿入・更新・削除注文を追加する、確定前の数量を訂正する、取り消した下書きを削除する。

同じ形の二つの集合なら、和は少なくとも一方、差は片方だけ、積（共通部分）は両方にある行を返します。例えば午前が {P01, P02}、午後が {P02, P03} なら、和は {P01, P02, P03}、午前から午後を引いた差は {P01}、積は {P02} です。

例題10問と解説

Study Quest編集部の自作問題です。先に答えを考えてから、各問の「解答と解説」を開いてください。

第1問　台帳と管理ソフト

二つの窓口で同じ注文台帳を扱います。検索に加え、同時更新やアクセス権を管理する仕組みはどれですか。

  1. DBMS
  2. E-R図
  3. レコード
  4. インデックス
第1問の解答と解説

ア　DBMS

DBMSがデータの保管と利用を管理します。インデックスはDBMSが利用できる検索用の仕組みです。

第2問　受付コードで直接探す

受付コードC81に対応する画面設定を、コード一つで読み出します。最も直接的に対応するモデルはどれですか。

  1. 階層型
  2. キーバリューストア
  3. グラフ指向
  4. 網型
第2問の解答と解説

イ　キーバリューストア

C81をキー、画面設定を値として対応させれば、コードから値を取り出せます。

第3問　同じ注文に2行ある

O102には1行目のクッキーと2行目のレモネードがあります。行番号は各注文で1から付け直します。注文明細を一意に識別できるのはどれですか。

  1. 注文IDだけ
  2. 行番号だけ
  3. 数量だけ
  4. 注文IDと行番号の組合せ
第3問の解答と解説

エ　注文IDと行番号の組合せ

注文IDは一つの注文に共通し、行番号も別の注文で重なります。二つの値を合わせれば各明細を識別できます。

第4問　外部キーの重複

商品表にP01とP02があります。注文明細の商品IDは必須の外部キーです。何が登録できますか。

  1. P99の明細
  2. 商品IDがNULLの明細
  3. 別々の注文にP01の明細を1行ずつ
  4. 商品表にP01の行を2件
第4問の解答と解説

ウ　別々の注文にP01の明細を1行ずつ

明細側では参照先にあるP01を何度でも参照できます。商品表側の主キーP01は重複できません。

第5問　表記ゆれと設計

紙の集計でP-01とP01が同じ商品だと確認できました。このとき実施するデータクレンジングはどれですか。

  1. 商品名にインデックスを付ける
  2. 商品IDを正しい表記に統一する
  3. 全行を商品IDの降順にする
  4. 数量の列だけを取り出す
第5問の解答と解説

イ　商品IDを正しい表記に統一する

内容を確認して、元データの表記や形式を整える作業です。並べ替えだけでは二つの表記が残ります。

第6問　商品表を分ける理由

受取場所が商品ごとに固定で、P01の場所を今後すべて「西口」に変えます。食い違いを防ぎやすい設計はどれですか。

  1. 受取場所を商品表に持たせ、明細は商品IDで参照する
  2. 商品IDを削除し、各明細に場所を書く
  3. 場所を複数の列に複製する
  4. 受取場所をすべて未入力にする
第6問の解答と解説

ア　受取場所を商品表に持たせ、明細は商品IDで参照する

場所の更新先が商品表のP01の1行にまとまります。明細から商品IDを使って参照できます。

第7問　大量の行から検索

取引が増え、商品IDを条件にした検索を繰り返します。読取りを改善できる可能性がある一方、書込みの維持コストも伴うのはどれですか。

  1. 明細を同じ数だけ複製する
  2. 主キーの値をすべて同じにする
  3. 数量を空欄にする
  4. 商品IDにインデックスを追加する
第7問の解答と解説

エ　商品IDにインデックスを追加する

DBMSが商品IDを手掛かりに行を探せる場合があります。更新時には索引も維持する必要があります。

第8問　結果の列を絞る

前掲の明細に商品名を補い、数量が2以上の行から商品名だけを表示します。必要な関係演算はどれですか。

  1. 選択だけ
  2. 結合と選択
  3. 結合・選択・射影
  4. 射影だけ
第8問の解答と解説

ウ　結合・選択・射影

商品名は商品表から結合で得て、数量の条件で行を選択し、最後に商品名の列を射影します。結果はレモネードとクッキーです。

第9問　件数と個数を分ける

レモネードの明細が2個と1個の2行あります。レモネードの販売個数と明細数はそれぞれいくつですか。

  1. 2個、3件
  2. 3個、2件
  3. 2個、2件
  4. 3個、3件
第9問の解答と解説

イ　3個、2件

個数は数量列の合計で2＋1＝3。明細数は数量にかかわらず行を数えるので2件です。

第10問　両方の時間帯に売れた商品

午前にP01とP02、午後にP02とP03が売れました。両方に出てきた商品を求める演算と結果はどれですか。

  1. 積（共通部分）でP02
  2. 差でP01とP03
  3. 和でP02
  4. 積（共通部分）でP01とP03
第10問の解答と解説

ア　積（共通部分）でP02

両集合に含まれる商品IDはP02だけです。和なら少なくとも一方に含まれる3種類すべてが残ります。
