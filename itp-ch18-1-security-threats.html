受付名簿のどこが弱く、何が起こり得るか

架空の文化祭で、申込者の連絡先、受付名簿、案内サイトを扱います。データ、端末、運営に必要なサービスは情報資産です。誰かに見られないようにする機密性、勝手に変えられないようにする完全性、必要なときに使える可用性の3つを、守りたいものから考えます。

同じ名簿でも被害の形が違う
脅威の種類文化祭での例
人的誤送信、盗み見、紛失、意図的な持出し。
技術的マルウェア感染、ソフトの欠陥を突く攻撃。
物理的浸水、停電、機器の破壊や妨害。

セキュリティホールは攻撃に悪用され得る弱点です。ソフトの不具合に限らず、引継ぎ不足や過剰な権限など、運用にも脆弱性はあります。シャドーITは組織の承認を得ずに個人用のクラウドなどを業務へ持ち込むことです。安全な製品でも、管理者が共有先や退職後の権限を把握できないと問題が起こり得ます。

感染の広がり方と、感染後にすることを分ける

種類ごとに、広がり方か被害かに注目する
用語見分ける手掛かり
ウイルス・マクロウイルス別のファイルなどに感染する。文書のマクロを使うものもある。
ワーム宿主ファイルに寄生せず自己増殖し、ネットワークなどで広がる。
トロイの木馬便利なアプリなどを装い、実行すると別の処理を行う。
ボット・RAT外部から操作を受ける。多数のボットはボットネットを構成することがある。RATは遠隔操作に使われる。
スパイウェア・キーロガー利用者情報をひそかに集める。キー入力を記録するものがキーロガー。
ランサムウェアデータを暗号化するなどして使えなくし、金銭などを要求する。
ファイルレスマルウェアメモリーや正規ツールなどを使い、典型的な実行ファイルだけでは見つけにくい。

バックドアは通常の確認を迂回できる入口、ルートキットは侵入や活動を隠すために使われることがある道具です。ポートスキャンやフットプリンティングは、公開されている入口や情報を調べる段階です。ファイル交換ソフト自体が全てマルウェアというわけではありませんが、未確認のファイルや公開範囲の設定がリスクになります。

何をだまし、どこを狙う攻撃か

標的型攻撃では特定の組織や人を狙います。水飲み場型攻撃は標的がよく訪れるサイトなどを悪用し、APTは特定の目標への持続的な攻撃を指します。スパムは迷惑な大量送信、メールボムは大量メールなどによる妨害、ワンクリック詐欺はクリックだけで契約したかのように装って請求する手口です。ダークウェブには窃取情報の流通などの悪用例があります。

Web攻撃は、どこで意図しないことが起きるか
用語見分けるポイント主な守り
XSS他の利用者のブラウザでスクリプトを実行させる出力先に応じたエスケープなど
CSRFログイン中の利用者の権限で望まない操作を送らせるCSRFトークンなど
SQLインジェクション入力をDBへの命令として扱わせるプレースホルダーに値を束縛
クリックジャッキング画面の重なりで別の操作をクリックさせるフレームへの埋込みを制限
ディレクトリトラバーサル意図した場所の外にあるファイルを読ませるアクセス可能なパスを限定
ドライブバイダウンロードサイトを閲覧した端末へ不正な処理を仕掛けるOS・ブラウザの更新など
バッファオーバーフロー想定した領域を越えて書き込ませる境界の検査や修正の適用
通信の途中やサービスを狙う攻撃
攻撃何が起きるか
中間者・MITB前者は通信相手の間に入り盗聴や改ざんを狙う。後者は端末のブラウザ内で表示や送信内容を改ざんする。
IPスプーフィング・DNSキャッシュポイズニング前者は送信元IPを偽る。後者は名前解決の一時記憶に偽情報を混ぜる。
セッションハイジャック・リプレイ前者は他人のセッションを乗っ取る。後者は過去の通信などを再送する。
第三者中継・踏み台前者はメールサーバが無関係な第三者の配送を許してしまう。後者は侵害した機器を別の攻撃の中継などに使う。
DoS・DDoS負荷をかけてサービス利用を妨げる。DDoSでは多数の発信元などに分散する。
ゼロデイ・クリプトジャッキング前者は修正が利用できる前などに脆弱性を突く。後者は他人の計算資源を無断で暗号資産の採掘に使う。
プロンプトインジェクション・敵対的サンプル前者は入力や参照文書の指示で生成AIの意図した動作を崩す。後者は誤認識を誘うよう調整した入力。

クラッキングは不正にシステムへ侵入したり破壊したりする行為を指します。なりすましは相手や利用者を偽る行為です。ソフトの正規機能でも、権限や使い方によって攻撃に悪用され得ます。

例題10問と解説

Study Quest編集部の自作問題です。先に答えを考えてから、各問の「解答と解説」を開いてください。

第1問　名簿を持ち出せる状態

受付の紙の名簿が離席時も通路から取れます。この場面の脆弱性はどれですか。

  1. 名簿の連絡先
  2. 誰でも取れる置き場所
  3. 撮影による漏えい
  4. 受付停止
第1問の解答と解説

イ　誰でも取れる置き場所

脆弱性は脅威を受けやすくする弱点です。連絡先は資産、漏えいは被害です。

第2問　案内が開かない

案内サイトが過負荷で開けません。最も直接的に損なわれたのはどれですか。

  1. 真正性
  2. 完全性
  3. 可用性
  4. 機密性
第2問の解答と解説

ウ　可用性

必要なときに使えないので、可用性が失われています。

第3問　振込先が急に変わる

業者の担当を名乗るメールで、今日だけ別口座へ振込を求められました。まず何をしますか。

  1. 登録済みの電話番号で確認
  2. メールに書かれた番号だけに電話
  3. 急いで振り込む
  4. 添付の指示だけで登録
第3問の解答と解説

ア　登録済みの電話番号で確認

BECを想定し、メールと独立した既知の連絡先で変更を確かめます。

第4問　自動で広がる

別のファイルに寄生せずネットワークで自己増殖します。何の特徴ですか。

  1. スパム
  2. バックドア
  3. キーロガー
  4. ワーム
第4問の解答と解説

エ　ワーム

自己増殖して伝播するという特徴がワームに該当します。

第5問　別サービスから流出

他サービスで流出したIDとパスワードの組が試されました。どの攻撃ですか。

  1. 総当たり攻撃
  2. パスワードリスト攻撃
  3. 中間者攻撃
  4. メールボム
第5問の解答と解説

イ　パスワードリスト攻撃

漏えい済みの組合せを再利用する点が、リスト攻撃の手掛かりです。

第6問　表示を見るだけで実行

掲示板に投稿された内容で、閲覧者のブラウザが意図せずスクリプトを動かします。何ですか。

  1. CSRF
  2. DDoS
  3. XSS
  4. SQLインジェクション
第6問の解答と解説

ウ　XSS

閲覧者のブラウザでスクリプトが実行されるのがXSSです。DBへの命令に混ぜるのはSQLインジェクションです。

第7問　ログイン状態を悪用

受付係が別サイトを開いたら、ログイン中の受付サイトに変更要求を送らされました。どれですか。

  1. CSRF
  2. ワーム
  3. DNSキャッシュポイズニング
  4. BEC
第7問の解答と解説

ア　CSRF

ログイン状態などを悪用して、利用者が意図しない要求を送らせるのがCSRFです。

第8問　復元しても別の被害

注文表を暗号化し、盗んだ名簿も公開すると脅されました。何を想定しますか。

  1. 水飲み場型攻撃
  2. ワンクリック詐欺
  3. 辞書攻撃
  4. 二重脅迫
第8問の解答と解説

エ　二重脅迫

使えなくする被害と、盗んだデータを公開するという脅しが重なっています。

第9問　多数の端末から集中

多数の侵害端末から案内サイトへ要求が集中しています。狙いがサービス妨害ならどれですか。

  1. MITB
  2. DDoS
  3. セキュアブート
  4. ポートスキャン
第9問の解答と解説

イ　DDoS

分散した発信元から負荷をかけて利用を妨げるのがDDoSです。

第10問　データベースの命令

申込フォームへの入力がDBへの命令として解釈されます。どの対策が直接的ですか。

  1. ファイル名を長くする
  2. 受付端末を施錠する
  3. プレースホルダーに値を渡す
  4. バックアップの頻度だけ増やす
第10問の解答と解説

ウ　プレースホルダーに値を渡す

SQLの構造と入力値を分け、入力が命令として扱われるのを防ぎます。
