ITパスポート 16-2 トランザクション処理

文化祭の最後の1個を題材に、コミット、排他制御、ACID、デッドロック、障害回復を図解と例題で学びます。

在庫を減らす処理と、注文を残す処理をひとまとめにする

文化祭の模擬店で、残り1個のレモネードが売れました。在庫を1減らしても、注文が記録されなければ受付で引き渡せません。この2つを一つの処理単位にまとめるのがトランザクションです。注文確定前の状態は在庫1、注文なしとします。

コミットは処理の変更を確定すること、ロールバックは未確定の変更を取り消すことです。例えば注文番号の重複で記録に失敗したとき、在庫だけ減らして処理を終えると帳尻が合いません。両方を同じトランザクションに含めます。

一貫性には、在庫が負にならない制約や、明細の商品IDが商品表を参照する制約などが関わります。アプリ側のルールも適切に実装する必要があります。独立性をどこまで強く保つかは、分離レベルなどの設計に関わります。

最後の1個に二つの注文が入ったら

このように複数の処理が同じデータを扱うときに整合性を保つ仕組みが同時実行制御です。ロックで両立しない操作を制限するのが排他制御で、ロックを解放することをアンロックと呼びます。典型的な説明では、共有ロックは別の共有読取りと両立し、排他ロックは競合するロックを待たせます。実際に読取りが待つかは製品やロックの種類によります。

AがP01を、BがP02を先にロックし、次に互いのロックを待つと、どちらも先へ進めません。この待ちの輪がデッドロックです。対策は、ロックする順序を統一することです。検出時にDBMSが一方を取り消す場合は、失敗した処理を初めからやり直す設計も使われます。片方だけが待っている状態なら、先行処理の終了で進めることがあります。

2相コミットメントは複数のDBなどにまたがる確定の調整です。調整役が故障すると、準備済みの参加側が結果を待つ場合もあります。

ログとバックアップで、どの状態に戻すか決める

ログ（ジャーナル）は、データベースの変更を記録するものです。試験で「更新前ログ」「更新後ログ」と示されたら、どの状態を取り消し、どの状態を再現するかを時間順に考えます。ログに残す情報や回復手順はDBMSによって異なります。

チェックポイントは、変更をディスクへ反映する処理と連携し、回復でログをどこから確認するかの目印になるものです。たとえばPostgreSQLのWALでは、再起動時に関連するチェックポイントの情報を使って、そこから必要なログを再生します。チェックポイントだけで、故障したディスクを復元するためのバックアップが手に入るわけではありません。

設問の条件で回復方法を選ぶ
状況考えること
1件の注文が未確定のまま失敗その処理の変更を取り消す。
保存装置が故障し、予備機に復元バックアップを戻し、揃っているログで必要な時点まで進める。
ログが途中から失われた失われた区間を越えて直前まで復元できるとは判断できない。

例題10問と解説

Study Quest編集部の自作問題です。先に答えを考えてから、各問の「解答と解説」を開いてください。

第1問　注文を残せなかった

在庫1から1個減らした後、注文の登録に失敗しました。両方を同じトランザクションに入れていた場合の結果はどれですか。

  1. 在庫0、注文なし
  2. 在庫1、注文1件
  3. 在庫1、注文なし
  4. 在庫0、注文1件
第1問の解答と解説

ウ　在庫1、注文なし

注文が失敗したので処理をロールバックします。在庫の変更も取り消され、元の1個に戻ります。

第2問　結果を確定する

在庫を減らし、注文番号も保存できました。両方の変更を確定する操作はどれですか。

  1. 射影
  2. コミット
  3. ロールバック
  4. 選択
第2問の解答と解説

イ　コミット

コミットでトランザクションの結果を確定します。ロールバックは未確定の変更を取り消す操作です。

第3問　故障しても注文が残る

確定した注文を、障害後も保持できるようにするACIDの特性はどれですか。

  1. 耐久性
  2. 独立性
  3. 原子性
  4. 一貫性
第3問の解答と解説

ア　耐久性

コミット済みの結果が失われない性質が耐久性です。原子性は一連の処理が部分的に残らないことです。

第4問　在庫を負にしない

在庫が0以上であるという制約を、処理の前後で満たします。この説明が指す特性はどれですか。

  1. 耐久性
  2. 独立性
  3. 原子性
  4. 一貫性
第4問の解答と解説

エ　一貫性

在庫が0以上というルールを満たすことに着目するので一貫性です。

第5問　待った後の在庫

在庫は最初1個。窓口Aがその1個を販売して確定しました。窓口Bがロックの解放を待っていたとき、Bの次の操作はどれですか。

  1. 最初に読んだ1を使って販売する
  2. 最新の在庫を確認して0なら販売しない
  3. 他の商品の在庫を減らす
  4. Aの確定済み注文を取り消す
第5問の解答と解説

イ　最新の在庫を確認して0なら販売しない

ロックの解放後は最新の値で判定します。Aの販売で残りは0なので、Bは売り切れを伝えます。

第6問　互いに待つ

AはP01をロックしてP02を待ち、BはP02をロックしてP01を待っています。何が起きていますか。

  1. 一方だけが待っている
  2. ロールフォワード
  3. デッドロック
  4. レプリケーション
第6問の解答と解説

ウ　デッドロック

相手の処理が終わらなければどちらも先に進めません。両者が同じ順で資源をロックすれば、この待ちの輪を防げます。

第7問　二つのDBを同じ結果にする

注文DBは準備できましたが、在庫DBは準備できませんでした。2相コミットメントの調整役はどうしますか。

  1. 注文DBだけ先に確定
  2. 両方に確定を指示
  3. どちらかを無作為に確定
  4. 全体を取り消す方針を伝える
第7問の解答と解説

エ　全体を取り消す方針を伝える

確定を指示するのは参加側がそろって準備できた場合です。一部だけ先に確定させません。

第8問　バックアップの後の販売

在庫5個のバックアップを戻しました。その後に2個と1個の販売が確定しており、ログも揃っています。障害前までの回復方法と個数はどれですか。

  1. ロールフォワード、2個
  2. ロールフォワード、5個
  3. ロールバック、2個
  4. ロールバック、8個
第8問の解答と解説

ア　ロールフォワード、2個

確定済みのログを順に適用します。5−2−1＝2個になります。

第9問　ログの始点を見つける

再起動後に、変更ログをどこから処理するかの手掛かりになるものはどれですか。

  1. 主キー
  2. チェックポイント
  3. E-R図
  4. ビュー
第9問の解答と解説

イ　チェックポイント

チェックポイントは回復で必要なログを見つける目印になります。保存装置全体のバックアップとは役割が違います。

第10問　更新前と更新後

注文が未確定で、在庫が8から6に変わった後に処理が失敗しました。更新前後の値をログに記録するモデルでは、取り消しに使うのはどれですか。

  1. 更新後の6
  2. 更新後の6をさらに2減らした4
  3. 更新前の8
  4. 新しく採番した注文ID
第10問の解答と解説

ウ　更新前の8

未確定の変更を取り消すので、処理前の8に戻します。確定済みの変更を再現する場合は更新後の情報を使います。
