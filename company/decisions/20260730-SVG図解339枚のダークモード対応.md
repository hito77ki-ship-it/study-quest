# 【稟議】SVG図解339枚のダークモード対応

**起案日：** 2026年7月30日
**ステータス：** ✅ 承認済み（2026-07-30）。既存339枚は現状維持、新規図解から暗背景対応。CLAUDE.mdコーディング規約に明文化
**契機：** 取締役提供のダークモードのスクリーンショットで、図解が白くまぶしいことを確認

---

## 1. 事象

| 項目 | 実数 |
|---|---|
| SVG図解の総数 | 419枚 |
| **明るい背景（#C8以上）を持つもの** | **339枚** |
| 暗い背景 | 0枚 |
| 背景矩形なし（透過） | 80枚 |
| `<img src="*.svg">` での埋め込み箇所 | 201箇所 |

`article-widgets.js` のダークモード対応は `html[data-theme="dark"] .container picture` で**影と枠線を付けるだけ**で、画像の明るさは変えていない。結果、ダーク背景（`#0B0F17`）の中に白い図解が並ぶ。

---

## 2. ファクトチェックリサーチ

### 一般的な手法とその可否

[Ctrl blog「The best method for embedding dark-mode friendly SVG in HTML」](https://www.ctrl.blog/entry/svg-embed-dark-mode.html)（2021）で各方式が比較されている。

**SVG内部に `@media (prefers-color-scheme:dark)` を書く方法は、`<img>` 経由でも動作する。**

```xml
<svg xmlns="http://www.w3.org/2000/svg">
  <defs><style>
    @media (prefers-color-scheme:dark){ svg{background-color:black} }
  </style></defs>
</svg>
```

- Firefox：完全に動作
- Chromium：動作するが、配色変更時に再描画されないバグ（[issue #1093736](https://bugs.chromium.org/p/chromium/issues/detail?id=1093736)）
- **Safari：非対応。** `prefers-color-scheme` を画像バッファで評価しない（[bug #199134](https://bugs.webkit.org/show_bug.cgi?id=199134)）。**回避策なし**

当サイトのSVGは**414枚が既に内部に `<style>` を持っている**ため、技術的にはこの方式が使える状態にある。

### しかし、この方式は当サイトでは使えない

**決定的な理由：当サイトは System / Light / Dark の3択トグルを持っている。**

SVG内部の `prefers-color-scheme` は**OSの設定**に従う。サイトの `data-theme` とは連動しない。したがって：

| OSの設定 | サイトのトグル | ページ本体 | SVG図解 | 結果 |
|---|---|---|---|---|
| ライト | **Dark** を選択 | 暗い | **明るいまま** | ズレる |
| ダーク | **Light** を選択 | 明るい | **暗くなる** | ズレる |
| ライト | System | 明るい | 明るい | ○ |
| ダーク | System | 暗い | 暗い | ○ |

**トグルで明示的に選んだユーザーほど、図解がページと食い違う。** これは現状（常に明るい）より悪い。**この方式は却下する。**

## 3. 取りうる選択肢

### 案A：ダークモード時に `<img>` へCSS filterを当てる

```css
html[data-theme="dark"] .container img[src$=".svg"]{ filter:brightness(.92) contrast(1.02); }
```

- ○ `data-theme` に連動するため、**トグルと必ず整合する唯一の方法**
- ○ 1箇所の修正で339枚に効く。SVGファイルは触らない
- ✗ **色を歪めるリスク。** 工業簿記のフロー図は色分けに意味がある（材料＝橙・賃金＝青・製造間接費＝紫…）。減光しすぎると識別性が落ちる
- ✗ 「まぶしさ」は緩和されるが解決はしない。白は白のまま少し暗くなるだけ

### 案B：ダーク版SVGを別途用意して `<picture>` で切り替える

- ○ 最も美しい結果になる
- ✗ **339枚の作り直し。非現実的。** しかもトグルとの連動には `prefers-color-scheme` を使うことになり、案の前提が崩れる

### 案C：何もしない（CEO推奨）

**「白い図解が浮いている」ことは、必ずしもバグではない。**

多くのサイトは図解を意図的に白いカードとして表示する。ダーク背景の上に白い紙が置かれているデザインとして成立する。実際、`html[data-theme="dark"] .container picture` は**すでに影と枠線を付けており**、カードとして見せる方向に半分進んでいる。

### 案D：カードとして明示的に仕上げる（案Cの発展形）

図解自体は触らず、**囲みを「意図的な白いカード」として仕上げる。** 余白・角丸・影を調整し、偶然浮いているのではなく設計されたものに見せる。色を1ピクセルも歪めない。1箇所の修正。

## 4. CEOジョブズの所見

### 新しい評価順に照らすと、これは今やることではない

1. **収益に直結するか** — しない。図解の明るさは成約に影響しない
2. **見つけてもらえる状態に近づくか** — しない。SEOにもインデックスにも無関係
3. **ユーザーの人生を本当に変えるか** — わずかに寄与する

**3番目にしか当たらない。** そして今日、私は評価順を変えた理由として「CLSを0.032にするのに長時間を使い、その間29記事に収益導線がないことに気づかなかった」と書いた。**SVGの明るさに時間を使うのは、まったく同じ過ちである。**

### ただし1点だけ、軽く扱えない論点がある

**ダークモードを選ぶ人は、まぶしさを避けたい人である。** 目の疲れ、光への過敏さ、夜間の使用。その人に339枚の白い図を見せるのは、**ダークモードを用意した目的そのものを損なう。**

これはアクセシビリティの問題であり、「デザインの好み」ではない。

### したがって推奨は「案D、ただし急がない」

- **案A（filter）は却下する。** 色に意味のある図解を機械的に減光するのは、可読性を犠牲にして眩しさを取る取引であり、割に合わない
- **案Dは安全で安い。** 色を歪めず、1箇所の修正で済む。ただし「まぶしさ」自体は解決しない
- **本質的な解決は案B（ダーク版の用意）だが、339枚では非現実的。** 新規に作る図解から順次ダーク対応する、という前向きな方針が現実的である

**提案：今日は何もしない。** 代わりに以下を決める。

> **これから新規に作るSVG図解は、暗い背景でも成立する配色（透過背景＋中間色の線・文字）で作る。** 既存339枚は当面そのまま。図解を差し替える機会が来たときに順次移行する。

これなら追加コストがほぼゼロで、時間とともに問題が縮小する。

## 5. 正直に書いておくこと

**この問題は、取締役がダークモードのスクリーンショットを送ってくださるまで見つからなかった。** 私はサンドボックスでレンダリングできないため、今日1日「ライト／ダーク両モードで確認してください」と何度もお願いしてきた。**その確認から、私が調べていなかった問題が出てきた。**

そして今日、私はこの記事のダークモード可読性について**コントラスト比を計算して「1.47:1で読めない」と報告し、それが誤りだった。** 存在しないCSSルールを前提にしていた。**実物を見た取締役の方が、計算した私より正確だった。**
