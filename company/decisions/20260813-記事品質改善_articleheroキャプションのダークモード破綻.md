## 1. 指摘① `.article-hero figcaption` のダークモード破綻（16ファイル）

### 何が起きているか

```css
/* 記事側（16ファイルすべてで同一の宣言） */
.article-hero{ background:var(--light); }
.article-hero figcaption{
  background: rgba(255,255,255,.82);   /* ← 半透明の白を固定 */
  color: var(--muted);                 /* ← 文字色は変数 */
  font-size:12px;
}

/* article-widgets.js */
html[data-theme="dark"]{ --light:#151A2A; --muted:#9BA7BB; }
/* .article-hero に関する規則は 0 件 */
```

**ダークモードで、82%の白が暗い面（`#151A2A`）に載って合成背景が明るいグレーになる一方、文字色だけが `#9BA7BB` に追従する。**

| テーマ | 合成背景 | 文字色 | コントラスト比 | WCAG AA（4.5:1） |
|---|---|---|---:|---|
| ライト | rgb(254,254,254) | #718096 | 3.94:1 | ❌ 未達 |
| **ダーク** | **rgb(213,214,217)** | **#9BA7BB** | **1.67:1** | ❌ **大幅未達** |

ライト側も12pxテキストとしてAAを満たしていないが、**本体はダーク側である。**

### ⚠️ これは第5のパターンである。過去4回のスキャン仕様では原理的に検出できない

| # | 検出日 | 記事側の背景 | 記事側の文字色 | widgets側 | 従来条件で検出 |
|---|---|---|---|---|---|
| 1 | 08-04 | — | — | カンマ区切りセレクタ欠陥 | ❌ |
| 2 | 08-05/06/07 | 16進 | dark未対応 | 独自クラス名を知らない | ✅ |
| 3 | 08-11(9回目) | 16進 | 16進 | `strong` の色だけ持つ | ❌（`198546f` で解消済み） |
| 4 | 08-11(10回目) | 16進 | `var()` | 変数をダークで再定義 | ❌ |
| 5 | **08-13** | **`rgba()` 半透明** | **`var()`** | **`.article-hero` 規則が0件** | ❌ |

**第4パターンまでは背景がすべて「16進で固定」だった。今回は `rgba()` の半透明である。**

08-11（10回目）に定めた検査仕様は「背景を16進として解決する」ものであり、**この16ファイルは1件も引っかからない。** 実際、本日の初回スキャンでも `.article-hero figcaption` は最初の実装では検出できず、**アルファ合成を実装して初めて出た。**

**08-11に「間違った検査条件は、検査しないことより危ない。検査したという安心を与えるからである」と書いた。今週それが自分に返ってきた。**

### 該当16ファイル

```
boki.html   boki1.html   boki2.html   boki3-progress.html   cpa.html
dokugaku-shikaku.html   fp.html   fp3.html   itp.html   keizoku.html
shihoshoshi.html   shikaku-list.html   shukatsu-shikaku.html
takken.html   toeic.html   zeirishi.html
```

**この分布が重い。16本のうち12本が資格ガイド本体——各資格の入口記事である。**

- `boki.html` `boki1.html` `boki2.html`（簿記）
- `cpa.html`（公認会計士）／`zeirishi.html`（税理士）
- `fp.html` `fp3.html`（FP）／`takken.html`（宅建）／`toeic.html`（TOEIC）
- `itp.html`（ITパスポート）／`shihoshoshi.html`（司法書士）
- **`shikaku-list.html` はサイトの資格選択ハブである**

**サイトの入口に集中している。** 検索から来た読者が最初に開くページ群であり、AdSense審査員が最初に見るページ群でもある。

### ⚠️ 修正方法に判断が要る点

- **原因は1箇所である。** 16ファイルすべてが同一の宣言をコピーして横展開したもので、全ファイルにローカルのダーク規則が無く、widgets にも `.article-hero` 規則が1件も無い。**したがって「widgets に `.article-hero figcaption` のダーク規則を1つ足す」だけで16本すべてが直る可能性が高い。**
- **ただし、記事側16ファイルの `background:rgba(255,255,255,.82)` を残したまま widgets 側で上書きするには `!important` が要る。** CLAUDE.md 項目16(b)は「`!important` 付きルールが記事側から打ち消せない形で漏れていないか」を警戒項目に挙げている。**`!important` を増やす方向は、08-04に検出したセレクタ欠陥と同じ土俵に足を踏み入れる。**
- **代案は、記事側16ファイルの1行を `background:var(--sq-surface-soft, rgba(255,255,255,.82))` のような変数ベースに書き換えること。** こちらは `!important` を増やさないが、16ファイルを触る。**08-11（10回目）の結論「成立するのは背景も文字色も両方とも変数の場合だけ」に沿うのはこちらである。**
- **どちらを採るかは、`!important` を増やす代償と16ファイル編集の工数の比較になる。** 私はこの稟議では断定しない。
- **ライト側の3.94:1をどうするかは別問題である。** 12pxの補足キャプションなので、フォントサイズを上げるか文字色を濃くするかの選択がある。**ダークを直すついでに触ると、直したつもりで両方中途半端になる危険がある。**

### 検査仕様への反映（必須）

**次回以降のコントラスト計算スクリプトは、以下2点を必ず含めること。**

1. **`rgba()` / `hsla()` のアルファを、親要素の背景に合成してから比を計算する。** 不透明色として扱うと、半透明の白が「白」と判定されて実際より高いコントラストに見える（もしくは背景が拾えず判定対象から落ちる）。
2. **`html[data-theme="light"]` 限定の規則を、ダーク側の値として流用しない。** 本日の初回スキャンは `.tip-box` `.warn-box` `.app-cta` を1.02〜1.07:1と誤検出したが、原因はライト限定の `color:#1A202C !important`（widgets 929〜938行）をダークの文字色として拾ったことだった。**項目27（フォールバック値の取り違え）と同じ系統の偽陽性で、方向が逆向きである。**

**本日の偽陽性は、修正前スクリプトで6クラス・延べ60箇所以上あった。そのまま報告していれば、壊れていない記事に工数が向かっていた。**

## 2. 指摘② `.nav-cta` / `.badge` / `.faq-q::before` — 白文字 × `#8CC63F` で 2.05:1（203ファイル）

```css
.nav-cta{ background:var(--green); color:#fff; font-size:13px; }
/* :root と html[data-theme="dark"] の双方で --green:#8CC63F */
/* widgets 側に nav-cta の color 上書きは 0 件 */
```

**ライトでもダークでも 2.05:1 で同一。** 13pxテキストなのでWCAG AAは4.5:1が必要である。

`.nav-cta` は**全203ファイルのヘッダーCTAボタン**。`.badge` と `.faq-q::before` は今回15本のうち5本で使用。

### ⚠️ これは指摘①とは性質が全く違う

**指摘①は「壊れた」——記事側とwidgets側が噛み合わずに事故が起きている。指摘②は「最初からそう設計されている」。**

`#8CC63F` はStudy Questのブランドカラーであり、`--green` として全体で使われている。**白文字を載せる限り、この緑では4.5:1に届かない。** 4.5:1を満たすには、

- ボタンの背景を `--green2`（`#6AAF2B`）以下の濃さにする → **ブランドの印象が変わる**
- 文字色を濃色（例：`#0A0A0F`）にする → **緑地に黒文字。既に `.app-cta a` はこの配色を採っている**
- フォントサイズを18.66px太字以上にする → **ヘッダーのレイアウトが変わる**

**いずれもブランドとレイアウトの判断を伴う。CEOの単独判断で決める範囲を超えている。**

### 私が今回できないこと（正直に書く）

**このタスクの実行環境にはブラウザをレンダリングしてスクリーンショットを撮る機能がない。** 2.05:1という数字は計算値であり、**実際にヘッダーのボタンがどれくらい読みにくいかを私は見ていない。**

緑地に白文字のボタンは実務でよく見る配色で、**「計算上AA不適合だが実用上は読める」という判断があり得る。** 一方で、AdSense審査やアクセシビリティの観点から見れば203ページ全部が該当する。

**したがって本件は「要目視確認」として報告に留め、断定的な改善案は書かない。**

## 3. CEOジョブズの所見

**指摘①について。**

これで5週連続、ダークモードの破綻を新しいパターンで検出している。毎週「これで検査条件は固まった」と思い、翌週それが崩れる。

**今週の崩れ方はとくに悪い。** 08-11（10回目）に「検査条件はクラス名でも出自でもなく、最終的に適用される前景色と背景色のペアを両テーマで解決してコントラストを計算する以外にない」と結論した。**その結論自体は今週も正しかった。崩れたのは実装である。** 「解決する」の中にアルファ合成が入っていなかった。

**正しい方針を立てても、実装の1行が抜ければ検出は0件になる。そして0件は「問題なし」と報告される。**

もう1つ、今週の16ファイルの並びを見てほしい。`boki.html` `cpa.html` `fp.html` `takken.html` `toeic.html` `zeirishi.html` `shikaku-list.html`——**これは「Study Questで一番読まれるページ」のリストとほぼ同じである。** 論点記事ではなく、入口である。**5週間ダークモードを追いかけて、いちばん人が来る場所が最後に出てきた。** 監査がローテーションで論点記事から回っていたからだ。

**指摘②について。**

これは私が決める話ではないので、判断を仰ぐ。ただ1つだけ言っておくと、**同じサイトの `.app-cta a` は「緑地に `#0A0A0F` の黒文字」を採っている。** つまりStudy Questは、既に緑地に濃色文字のボタンを持っている。**ヘッダーのCTAだけが白文字である。** 統一されていないこと自体は事実として報告しておく。

「それはユーザーの人生を本当に変えるか？」——figcaptionは図解の説明文である。読めなくても記事の本論は読める。**だが16ファイルの中身は「その資格の入口記事」であり、図解はそこで最初に目に入る要素である。** ダークモードを選んだ読者は、入口で意味の取れないグレーの帯を見ることになる。
