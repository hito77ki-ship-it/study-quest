# 稟議書：定期自動化を監査と判断支援へ再設計する

**起票日：** 2026-09-14
**起票者：** CEO ジョブズ
**ステータス：** 取締役承認済み（2026-09-14、チャットで全項目を承認）
**種別：** 運用プロセス・監査実装の変更（記事本文・UI・外部送信は対象外）

---

## 1. 本稟議の指摘は6件

今回、有効14本・停止9本の定期自動化とGitHub Actionsを対象に監査した。この6件は**全自動化設定を対象にした実数**であり、記事監査の件数ではない。

1. 日次の自動commit・push・PR・自動マージは、定期自動実行を監査・レポートに限定する運用ルールと矛盾する。
2. AdSense監査が202記事中164件・171件という広すぎる候補を出し、判断の優先順位として機能していない。
3. 28日移動窓だけの順位比較は、表示停止を「横ばい」と誤認しうる。
4. 生成AI機能の表示とAI参照流入は小さいため、短い週次比較で効果を断定できない。
5. ローカルの日次本番監視はGitHub Actionsと重複し、実際に行わない390px確認まで報告対象にしていた。
6. 自動化健全性監査が月1回では、設定変更直後の逸脱を早く検出できない。

## 2. 承認した変更

| 対象 | 変更 | 安全境界 |
|---|---|---|
| `study-quest-commit-push` | 停止する。公開準備の読み取り監査は既存の `study-quest-3` に統合する。 | commit・push・PR作成・マージをしない |
| `study-quest-3` | 承認、一次情報、実施報告、検証、公開証跡のそろった案件だけを「人が隔離cloneで実装可能」と表示する。 | 状態を書き換えない |
| `study-quest-adsense` | GSC表示、生成AI機能の表示、AI参照流入、収益導線を優先度に使い、1回最大5記事・前回から変化した候補だけを出す。 | 記事も稟議も自動作成しない |
| `study-quest-keyword-ranking-tracker` | 非重複期間を比較し、上位から消失または表示50%以上減のクエリだけ3か月日別推移を確認する。 | ログイン情報を入力せず、取得不能値を推測しない |
| `study-quest-gsc-ga4` / `study-quest-gsc-ga4-pdca` | 第1金曜の28日単位の測定・判断へ変更し、生成AI機能とAI参照流入を分けて記録する。 | 因果・収益を断定しない |
| `study-quest-production-site-monitor` | 停止する。GitHub Actionsの読み取り監視を正本にする。 | 外部送信・修正をしない |
| GitHub Actions本番監視 | 固定の代表8ページに加え、sitemapで更新日が新しい4ページを確認する。 | 読み取り・artifact出力のみ |
| `study-quest-5` | 月次から週次へ変更する。 | 設定を自動変更しない |
| `study-quest-2` | 公式情報の監視対象は高影響ページを優先する。 | 一次情報を実際に開けない場合は推測しない |

## 3. 明示的に対象外とするもの

- AdSense再申請、GSCの再送信、SNS・Noteなどの外部送信
- 記事本文、図解、UI、広告設定の自動変更
- 自動commit・push・PR作成・自動マージ

これらは本稟議の承認をもっても自動化しない。記事・UIの変更は、既存のファクトチェック、稟議、取締役承認、実装、実施報告、検証の順序を守る。

## 4. 検証方法

1. 自動化設定で、書き込み・外部送信を伴う有効タスクが残っていないことを確認する。
2. GitHub Actionsで `git diff --check`、品質ゲート、AdSenseポリシーゲート、内部リンク監査が継続することを確認する。
3. `run-media-audits.mjs --mode production --no-write` で、基本8ページとsitemap上の最近更新4ページが選ばれることを確認する。
4. 設定更新後の最初の各実行で、候補数の上限・比較期間・安全境界が守られていることを人が確認する。
