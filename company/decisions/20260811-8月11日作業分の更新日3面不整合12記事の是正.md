## 2. ファクトチェック

### 事実確認の方法

1. `git status --porcelain` で8/11に変更された98 HTMLを特定
2. 各ファイルについて `git show HEAD:<file>` と作業ツリーを比較し、**`<style>` `<script>` `<head>` を除去してタグを剥がした可視文字数の純増減**を測定
3. JSON-LD の `dateModified`、本文の「更新日：YYYY年M月D日」、`sitemap.xml` の `<lastmod>` を機械抽出して突合
4. 見出し構造は `<h2>` を順に抽出して目視確認

### 確認できた事実

- **8/11に変更された98 HTMLのうち、本文が150字以上動いたのは15本だけ**だった。残り83本はダークモードCSS・カテゴリサムネイル・og:image差し替え・CTA導線で、**本文の実質変更ではない**
- 15本の内訳：**3面すべて2026-08-11で正しいのが3本**（`boki2-zairyouhi` / `takken-vs-mansion` / `fp3`）、**lastmodのみ取りこぼしが6本**、**3面すべて据え置きが6本**
- `cpa-akirameta-shukatsu` と `shindanshi` は、dateModified が「2026-08-11」、lastmod が「2026-06-27」で**45日の食い違い**がある
- CLAUDE.md の「更新日を変更するときのルール」は **2026-08-11に更新されたばかり**である（本ファイル自体も未コミット）

### 測定方法についての自己訂正

**第5回の監査では、`<style>` を除去せずに可視文字数を数えていた。** その方式だと `cpa-dokugaku.html` のダークモードCSS追加（`html[data-theme="dark"] .danger-box{...}` など11行）が「本文801字追加」とカウントされる。**今回この誤りに気づき、除去して測り直した結果、対象は24本から15本に減った。**

**第5回の「本文追加あるのに日付据え置き24本」という数字は過大だった。訂正する。**

### 反証の検討：「1日のズレ（lastmod 8/10 vs dateModified 8/11）は実害があるか」

**単体では小さい。** Googleは lastmod を「クロール優先度のヒント」として扱い、絶対的な信頼は置いていない。1日のズレでインデックスが外れることはない。

**それでも是正すべき理由は2つ。**

1. `cpa-akirameta-shukatsu` と `shindanshi` の**45日ズレは1日ズレと同じ原因**（sitemap.xml が別ファイルだから取りこぼす）で発生している。原因が同じなら一緒に直す
2. CLAUDE.md が「3箇所を同じ日付で同じスクリプトから書き換える」と明文化している。**ルールを作った日に例外を作ると、ルールが死ぬ**

### 反証の検討：「(b)の3記事（boki2-ochita / cpa-yobikou / zeirishi）は8/10のままでよいのでは」

**よくない。** これらは8/10に本文を追加し、**8/11にさらに150〜182字を追加している。** 8/10の日付は8/10の変更を指しており、8/11の追加を反映していない。ただし**ズレは1日で、実害は最も小さい層である。** 取締役が「これは触らない」と判断しても、私は反対しない。

## 3. CEOジョブズの所見

**それはユーザーの人生を本当に変えるか？**

正直に言う。**この稟議の(a)(b)は、単体ではユーザーの人生を変えない。** sitemap の lastmod が1日ズレていることに気づく読者はいない。

**変えるのは(d)である。**

今日わかったことは、日付が12件ズレていたということではない。**同じ種類の変更に対して、記事ごとに違う判断をしていたということ**である。`chori.html` は日付を動かし、`daigakusei-keizai-shikaku.html` は動かさなかった。**どちらも同じ「カテゴリサムネイル＋本文追記」なのに。**

これは怠慢ではない。**判断基準が無いから、そのときの気分で決まっただけ**である。基準が無い状態で12件を直しても、**来週また同じばらつきが12件出る。** 直すべきは記事ではなく、判断の空白だ。

**シンプルさは究極の洗練である。** (d)の表は「更新する／しない」の2列しかない。迷う余地を残さないために、あえて曖昧な中間を作らなかった。

もう1つ、(c)について。**「まとめ」の後ろに本編を足すのは、読者にとって最悪の体験である。** 一度「終わった」と思った文章が再開する。8/10の作業でこの問題を8件見つけて稟議を立てたのに、**8/11の作業で新しく1件作った。** 対策を打った翌日に同じ形の傷を作っている。**独自性セクションを追記する作業手順に「まとめの前に入れる」の一言が無い。** ここは(d)と同じ構造の欠落である。

### 評価順に照らした判断

1. **収益に直結するか** → **間接的。** ただし `cpa-akirameta-shukatsu`（公認会計士＝アフィリエイト単価が最も高い領域）と `zeirishi` は収益導線を持つ記事群であり、クロール頻度は無関係ではない
2. **見つけてもらえる状態に近づくか** → **近づく。** 矛盾したシグナルを止めることは、新しいシグナルを送るより先に済ませるべき仕事である
3. **ユーザーの人生を変えるか** → (c)は少しだけ変える。まとめの後に本編が続かない方がいい

### 妥協点の自己申告

- **(b)の6記事のうち3記事（8/10→8/11の1日ズレ）は、効果がほぼゼロである。** 網羅性のために入れた。切ってよい
- **(d)の閾値「150字」に強い根拠は無い。** 実測値の分布（150字未満は83本、150字以上は15本）を見て、きれいに分かれる位置を取った。**数字そのものより、閾値が明文化されていることに意味がある**
- **(d)は「更新しない」側にhero画像追加を入れたが、これは議論の余地がある。** 図解の追加は読者への情報として意味があり、「見た目だけ」と言い切れない。**今回は「テキストが増えていないなら動かさない」で統一したが、より正確な線引きは運用してみないとわからない**
- **第5回のレポートで報告した「24本」は、私の測定ミスによる過大な数字だった。** 訂正して15本とする。**数字を出すときに測定方法を書いていなかったから、自分でも検証できなかった。** 今後は測定方法を必ず併記する
