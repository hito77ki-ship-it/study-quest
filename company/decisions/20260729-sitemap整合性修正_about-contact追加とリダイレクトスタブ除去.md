# sitemap.xml整合性の修正（about/contact追加・リダイレクトスタブ除去・lastmod追随）

**日付：** 2026年7月29日
**提案者：** CEO ジョブズ（週次技術SEO監査タスクより）
**決定者：** 取締役
**ステータス：** 承認・実行完了（2026-07-29）。about.html・contact.htmlをsitemapに追加（priority 0.5/0.4）、noindexのリダイレクトスタブboki3-ginko.htmlを除去、boki2-ochita.htmlのlastmodを2026-06-27→2026-07-27に追随。全URL207件についてXML構文・重複・ファイル実在・noindex混入を機械検証し、いずれも問題なしを確認。指摘どおり機械的置換によるlastmod一斉更新は行わず、実質更新のあった1件のみに限定した。

---

## ファクトチェック

sitemap.xml（204URL）と実在するHTMLファイル（206件）を双方向に突合した。前回7/27の監査では記事ファイルのみを対象にしていたため、固定ページを含めて洗い直した結果、以下3点の不整合が確認された。

### 1. 実在するのにsitemap未掲載：`about.html`（運営者情報）／`contact.html`（お問い合わせ）

両ページの現状：

| 項目 | about.html | contact.html |
|---|---|---|
| title | ○ 運営者情報｜スタディクエスト | ○ お問い合わせ｜スタディクエスト |
| description | ○ | ○ |
| canonical | ○ 自ページ正常 | ○ 自ページ正常 |
| noindex指定 | 無し（=インデックス対象） | 無し（=インデックス対象） |
| sitemap掲載 | **無し** | **無し** |

一方、同じ固定ページでも `privacy.html` `terms.html` `tokusho.html` はsitemapに掲載済み。法務系だけ登録して、運営者情報とお問い合わせが漏れているという抜け方をしている。

**AdSense観点での重み：** Googleのプログラムポリシーおよび審査実務において、運営者情報（About）と連絡手段（Contact）の存在は、サイトの信頼性を判断する基本要件として扱われる。E-E-A-Tの「Trust」を支える中核ページでもある。ページ自体は存在するのに検索エンジンへのインデックス依頼が出ていない状態は、せっかく用意した信頼シグナルが評価に反映されない可能性がある。

### 2. noindexページがsitemapに掲載されている：`boki3-ginko.html`

`boki3-ginko.html` は `boki2-ginko-chosei.html` への統合リダイレクトスタブ。ページ側の実装は正しい：

```html
<link rel="canonical" href="https://study-quest.net/boki2-ginko-chosei.html">
<meta http-equiv="refresh" content="0; url=https://study-quest.net/boki2-ginko-chosei.html">
<meta name="robots" content="noindex">
```

問題は、このURLがsitemap.xmlの29行目に `priority 0.8` `changefreq monthly` で登録されたまま残っていること。

sitemapは「インデックスしてほしいURLのリスト」であり、そこに `noindex` ページを載せるのは検索エンジンへの矛盾した指示になる。Search Consoleでは「送信されたURLに noindex タグが追加されています」というエラーとして計上され、繰り返されるとsitemap全体の信頼度低下につながる。

なお、この統合作業自体は2026-07-20に実施されており、そのときsitemapからの除去だけが漏れたものと推測される。

### 3. 実質更新にlastmodが追随していない：`boki2-ochita.html`

7/27に「ペルソナ分岐チェックリスト＋FAQ2問」を追加（13行追加。競合研究の承認済み提案の実装、コミット `b803c24`）。

- JSON-LDの `dateModified`：`2026-07-27` ← 正しく更新済み
- sitemap.xmlの `lastmod`：`2026-06-27` ← **更新されていない**

同一サイト内で更新日の申告が食い違っている状態。Googleは実質的な更新があったページを優先的に再クロールするため、追加したコンテンツの反映が遅れる。

**（補足）他ページのlastmodは触るべきではない：** 7/26のペルソナ統一（168ファイル）、7/27のJSON-LD一括修正（195ファイル）で大半のファイルのタイムスタンプが動いているが、これらは機械的置換であり本文の実質的更新ではない。Googleの公式ガイダンスは「lastmodは意味のある更新のみを反映すべき」としており、機械的変更で一斉にlastmodを更新すると、逆にsitemapの信頼度を落とす。**したがって今回の修正対象は、実質的なコンテンツ追加があった `boki2-ochita.html` の1件のみに限定する。**

## 提案内容

sitemap.xml に対する以下3つの修正のみ。HTMLファイル側の変更は一切不要。

1. **追加：** `about.html` と `contact.html` の2URLをsitemap.xmlに追加する
   - lastmod：実ファイルの最終実質更新日（2026-07-27）
   - priority：他の固定ページ（privacy/terms）と同水準に揃える
2. **削除：** `boki3-ginko.html` の1行をsitemap.xmlから除去する（HTMLファイル自体は残す。リダイレクトスタブとして機能させ続ける）
3. **更新：** `boki2-ochita.html` の lastmod を `2026-06-27` → `2026-07-27` に変更する

いずれもsitemap.xmlの数行の編集で完結し、記事本文・レイアウト・アプリ挙動には一切影響しない。

**実行後の推奨アクション：** Search Consoleからsitemap.xmlの再送信を行い、about.html / contact.html についてはURL検査からインデックス登録をリクエストする。

## ジョブズの所見

**これは前回の自分の見落としだ。まずそこを認める。**

7/27の監査で「sitemapにデッドエントリは無い、198件すべてに対応ファイルが存在する」と報告した。それ自体は事実だった。だが逆方向 — 実在するのにsitemapに無いページ — のチェックを、記事ファイルにしか掛けていなかった。固定ページを対象から外していた。その結果、運営者情報とお問い合わせという、AdSense審査で最初に見られる2ページの漏れを丸ごと見逃した。チェックの設計が甘かった。

そして問題の本質はそこにある。**AdSense合格を最優先目標に掲げているのに、審査官が「この人は誰で、どう連絡が取れるのか」を確認しに行く2ページのインデックス依頼を出していなかった。** 記事を200本磨き上げても、運営者が誰か分からないサイトは信用されない。記事の質で勝負する前段階の、名刺を出すという当たり前の部分が抜けていた。

`boki3-ginko.html` の件は実害こそ小さいが、性格が悪い。**Googleに向かって「このページを見に来てくれ」と言いながら、行った先に「見るな」と書いてある。** 一度なら誤差だが、こういう矛盾はsitemapという「サイト運営者からの申告書」の信頼度そのものを削る。統合作業のときに片付けておくべきだった後始末だ。

lastmodについては、あえて1件だけに絞った。ここ数日の一括置換で200近いファイルのタイムスタンプが動いているが、あれは実質的な更新ではない。全部のlastmodを今日の日付に書き換えれば「サイト全体を更新した」と申告できて気持ちはいいが、それは嘘だ。Googleは嘘をつくsitemapを信用しなくなる。**実際に中身を足した1本だけを正直に更新する。それが正しい。**

修正コストは sitemap.xml の数行。効果はAdSense審査における信頼シグナルの回復。**やらない理由が一つも見当たらない。**
