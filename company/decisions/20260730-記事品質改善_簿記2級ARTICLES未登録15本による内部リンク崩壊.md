## 1. 背景

`article-widgets.js` の `ARTICLES` オブジェクト（4行目〜）は、記事ファイル名 → `{label, title}` の対応表である。サイドバーの論点一覧と前後記事ナビは、この対応表を引けなかったファイルを**エラーも出さず黙って捨てる**設計になっている。

```js
// 2650行付近・サイドバー描画
const a = ARTICLES[f]; if(!a) return;

// 2236行付近・前後記事ナビ
(prev && ARTICLES[prev] ? `<a href="${prev}" ...>` : '<div></div>')
```

簿記2級の論点記事28本のうち、**15本が `ARTICLES` に登録されていない。**

## 2. ファクトチェックリサーチ

### 内部リンクとクロール・インデックスの関係（複数ソース）

- **内部リンクはGoogleのURL発見手段として第1位**であり、XMLサイトマップは第2位。複数経路で繋がれたページは発見が速く、クロール頻度も高い（LinkBoss / DigitalApplied）
- Web上のページの推定**25%が内部リンクを1本も受けていない**（オーファンページ）。オーファンページはサイトマップ経由でしか発見されず、**「重要度が低い」というシグナルになるため、クロールされてもインデックスに入りにくい**（ClickRank / SearchEngineZine）
- ホームから**2クリック圏内**のページに比べ、それより深いページのクロール頻度は**約70%低下**する（DigitalApplied）
- 内部リンクの整備でクロール効率が**40〜70%改善**した事例が報告されている（Upward Engine）

### 自社の状況との突き合わせ

当社は `company/reports/20260729-インデックス登録状況の再確認_過去レポートの訂正.md` および `20260724-インデックス回復状況フォローアップ*.md` の通り、**「クロール済み - インデックス未登録」が継続課題**である。

上記の未登録15本は、サイドバー論点一覧という**サイト内で最も安定した内部リンク源から丸ごと外れていた。** 記事本体からの相互リンクは生きているので完全なオーファンではないが、「重要度シグナルの供給が半分止まっていた」状態である。**インデックス未登録の原因の一部がここにあった可能性は無視できない。**

### 反対材料も記載する（誠実性のため）

- これらの記事は `sitemap.xml` に掲載されており、記事本文からの相互リンクも存在する。したがって**完全なオーファンではなく、内部リンク0本の状態ではない**
- したがって「これを直せばインデックスされる」と断定はできない。効果は**期待値としては高いが保証はできない**

## 3. CEOジョブズの所見

**これはユーザーの人生を変えるか。変える。** 簿記2級を独学している人間がサイドバーを開いて「工業簿記」を押したとき、そこに5本しか出てこない。実際には14本ある。**残り9本は、その読者にとって存在しないのと同じだ。** 材料費・労務費・経費・個別原価計算・総合原価計算・標準原価計算・直接原価計算・CVP分析——工業簿記の骨格そのものが、導線から消えていた。

「学習進捗 3/29」と表示しながら、サイドバーから辿れるのは14本しかない。**ユーザーは残り15本をどうやって読めというのか。** これは機能の不足ではない。**約束の不履行だ。**

さらに厳しく言えば、これは書いた記事を自分で使っていない証拠である。私は毎週の監査で「ダークモードの色が」「クラス名の衝突が」と細部を詰めてきたが、**その間ずっと、サイト最大シリーズの導線が半分死んでいることに気づいていなかった。** 前回も前々回もこの15本の中の記事を監査対象にしていたのに、`article-widgets.js` の登録状況を突き合わせていなかった。**細部を磨く前に、動線が繋がっているかを確認すべきだった。これは私の優先順位の誤りだ。**

**最優先目標との関係：**
- **検索上位表示：** 直結する。内部リンクはGoogleの発見手段の第1位であり、当社の継続課題である「クロール済み - インデックス未登録」に対して最も安価に打てる手である
- **AdSense合格：** 間接的に寄与する。サイト内を回遊できない構造は「ユーザーにとって有用なサイト」の評価を下げる

**シンプルさの観点：** これは機能追加ではない。**足りないデータを埋めるだけの、純粋な引き算の作業だ。** 新しいコードは1行も書かない。だから今日決める。

**妥協点を正直に書く。** 本来は `ARTICLES` と `BOKI*_FILES` という二重管理をやめ、単一の定義から両方を導出すべきである。それが本質的な解だ。しかし**それは今回やらない。** 二重管理の解消はリファクタリングであり、失敗すると全シリーズの導線が壊れる。今回は「登録漏れを埋める」ことだけをやり、構造改善は別稟議に分ける。**速く動くために、正しい設計を一度先送りする。これは意図的な妥協である。**

## 4. 提案する対応

### 案A（推奨）：ARTICLES に15本を追記する。それだけ

`article-widgets.js` の `ARTICLES` に、未登録15本の `{label, title}` を追記する。

- `label` は既存の2級記事と同じ `'簿記2級'` を使う
- `title` は各記事の `<h1>` を要約した短いラベルとする（既存エントリの粒度に合わせる。例：`boki2-kessan.html` → `'決算整理・財務諸表作成の第3問対策'`）
- **`BOKI2_COMMERCIAL_FILES` / `BOKI2_INDUSTRIAL_FILES` の並び順は一切変更しない。** 並び順を変えると前後記事ナビの繋がりが変わり、影響範囲が読めなくなる
- 記事HTMLファイルは1バイトも触らない

**この案の唯一の欠点：** 二重管理構造をそのまま残す。次に記事を追加したとき、また同じ漏れが起きうる。→ 実施項目でチェックリストに明文化して塞ぐ。

### 案B：二重管理を解消する（今回は却下）

`ARTICLES` を唯一の定義とし、`BOKI*_FILES` を `ARTICLES` のキーから導出する設計に変える。本質的な解だが、全シリーズの導線に影響するリファクタリングとなる。**今回は却下し、案A実施後に別稟議とする。**

### 案C：比較・派生記事4本もリストに登録する（判断を仰ぐ）

`boki2-hyojun-vs-jissai.html` / `boki2-kurinobe-shisan-vs-fusai.html` / `boki2-kotei-shisan-why.html` / `boki2-kotei-betsu-genka.html` は `BOKI2_COMMERCIAL_FILES` / `BOKI2_INDUSTRIAL_FILES` のどちらにも入っておらず、サイドバーも前後ナビも一切出ない。

簿記1級では `BOKI1_TOPIC_FILES` として比較記事も登録されているため**シリーズ間で扱いが非対称**である。ただしこちらは「論点シリーズの一覧に比較記事を混ぜると本数が膨らんで一覧が読みにくくなる」という意図的な設計の可能性があり、私の判断だけでは決められない。

**CEOとしての意見：** 混ぜるべきではないと考える。サイドバーは「論点を順に潰す」ための導線であり、比較記事はそこに割り込むと順序が壊れる。**代わりに「関連する比較記事」という別グループをサイドバーに設けるのが筋だと思うが、これは案Aとは別の話なので切り離したい。**

## 7. 反省（CEO所見の追記）

**私は今日の午前、この問題を見つけられる位置に何度もいた。**

「クロール済み - インデックス未登録」6ページの原因を分析し、内部リンクの重要性について書き、`article-widgets.js` を何度も開いて編集した。それでも `ARTICLES` と配列の突き合わせを一度もしなかった。

さらに悪いのは、その同じ日にLPのCLSを0.207から0.032へ下げるために長時間を費やし、**その過程で犯人の診断を5回連続で外した**ことだ。画像→CLS→フォント→圧縮→総ペイロードと、そのたびに「原因が分かりました」と報告し、5回とも違っていた。**その時間ずっと、サイト最大シリーズの導線が半分死んでいた。**

CLSを0.1未満に収めることと、工業簿記14本のうち9本がサイドバーから消えていることを直すこと。**どちらがユーザーの人生を変えるかは、比べるまでもない。** 私は測りやすい方を選んでいた。

**教訓：数字が出る作業は達成感があるが、達成感の大きさと重要度は無関係である。**
