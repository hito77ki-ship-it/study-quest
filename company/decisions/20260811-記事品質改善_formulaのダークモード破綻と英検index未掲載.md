## 1. 背景

### 1-1. `.formula` がダークモードで読めない（コントラスト 1.01:1）

2026-08-11の定例監査で、3記事8箇所のコントラスト比が **1.01:1**（WCAG AA基準 4.5:1）まで落ちることを検出した。

| ファイル | `.formula` 内の `<strong>` | 中身 |
|---|---|---|
| `fp3-finance.html` | 4箇所 | PER「**10倍**」「**1倍**」「**25倍**」等 — **計算の答え** |
| `fp3-nannichi.html` | 3箇所 | 「**①今日の日付を確認**」「**②60日後の日付を仮の受検日として設定**」「**③テストセンターの空き状況を見て、その付近で実際に予約**」 — **記事の中心である逆算3ステップの手順そのもの** |
| `fp3-lifeplanning.html` | 1箇所 | 「**約27.4万円/年**」 — **減債基金係数の計算結果** |

**潰れているのは装飾ではなく、記事が読者に届けたい答えと手順である。**（08-04に `boki3-kabushiki.html` で同じことを書いた）

### 1-2. 原因は、これまでのどのパターンとも違う

```css
/* 記事側のローカル <style> — 3本とも同一 */
.formula{background:#F7F9FF;border:1px solid #C3DAFE;border-radius:10px;
         padding:16px 20px;margin:20px 0;font-size:14px;color:#374151}

/* article-widgets.js が持つ .formula 関連ルールは、この2行だけ */
html[data-theme="light"] .formula strong{color:#111827 !important;}
html[data-theme="dark"]  .formula strong{color:#F8FAFC !important;}
```

**`html[data-theme="dark"] .formula{background:...}` が存在しない。**

したがってダークモードでは、
- 背景：記事側の `#F7F9FF`（ほぼ白）がそのまま残る
- 文字：widgets が `<strong>` を `#F8FAFC`（ほぼ白）に `!important` で強制する

**→ 白に白。コントラスト 1.01:1。**

ライトモードは `#111827` on `#F7F9FF` = 16.4:1 で問題ない。**ダークモードでのみ、しかも `<strong>` の中だけが消える。**

### 1-3. 08-07に立てた仮説が反証された

08-07の監査レポートで、私は次の表を作った。

| クラス | 出自 | 結果 |
|---|---|---|
| `.tip-box` `.warn-box` | **widgets が知る名前** | ✅ 無傷 |
| `.experience-box` | 独自 | ❌ 1.04:1 |

そして「**独自クラス名を使うな、ではなく『明るい背景を固定するなら文字色も固定するか dark 規則を書く』が正しいルールである。これなら機械で検査でき、全記事スキャンの検出条件として実装できる**」と結論した。

**`.formula` は widgets が知っている名前である。そして記事側は文字色（`color:#374151`）を固定している。** 08-07の検査条件では**1箇所も検出できない。**

### 1-4. 同型リスクを持つクラスを widgets 全体からスキャンした

「ダークモードで `strong` を `#F8FAFC` に強制するのに、同じクラスのダーク背景規則を持たない」クラス：

```

```

今回の15本ではこれらは使われていないが、**サイト全体では使われている可能性が高い。**

## 3. CEOジョブズの所見

**先週立てた仮説が、翌週に反証された。**

08-07に私はこう書いた。「壊れる条件が特定できた」。表まで作って、機械検査の条件に落とせると宣言した。**その条件では、今週の8箇所は1つも引っかからない。**

これ自体は悪いことではない。仮説を出して検証し、反例が出たら修正する——それが正しい進み方だ。**悪いのは、あのまま全記事スキャンを実装していた場合である。** スキャンは「0件」と報告し、我々は「ダークモード問題は解決した」と結論しただろう。**間違った検査条件は、検査しないことより危ない。検査したという安心を与えるからだ。**

3週間かけて分かったのは、破綻のパターンが3種類あるということだ。

| # | 発見 | 原因 | 08-07の条件で検出 |
|---|---|---|---|
| 1 | 08-04 | **widgets のセレクタ欠陥**（カンマ区切りに dark が付いていない）。ライト側が壊れた | ❌ |
| 2 | 08-05/06/07 | **記事側の dark 未対応**＋独自クラス名。widgets の救済網に掛からない | ✅ |
| 3 | **08-11** | **widgets が `strong` の色だけ面倒を見て、背景を見ていない。** 記事側が明るい背景を固定 | ❌ |

**共通しているのは「記事側の CSS と widgets の CSS が、それぞれ片方の属性だけを持っている」ことである。** 背景だけ、文字色だけ、`strong` だけ。**どちらも単体では正しい。組み合わさったときだけ壊れる。**

だから検査条件は、クラス名でも出自でもない。**「最終的に適用される前景色と背景色のペアを、ライト・ダーク両方で解決して、コントラストを計算する」——これしかない。** 遠回りに見えるが、3週かけて他の近道が全部だめだと分かった。

そしてもう1つ。**今回壊れたのは `.formula` である。** 名前のとおり、公式・計算式を入れるための箱だ。**記事の中で最も「答え」が入る場所である。** 08-04に「潰れているのは装飾ではなく計算の答えそのもの」と書いたが、これで4週連続で同じことを書いている。**偶然ではない。強調される場所ほど、記事側もwidgets側も色をいじる。だから衝突する。**

**英検9本の index 未掲載について。**

これは記入漏れではない。**1本や2本なら忘れたのだと思う。9本中9本なら、`index.html` に英検のカードセクションが存在しないということだ。** ARTICLES には全部登録されているので、内部リンク網には乗っている。**しかしサイトのトップページから、人間の読者が英検の記事に辿り着く経路が1本もない。**

英検はこのサイトで9本を投じたカテゴリである。**9本書いて、入口を作っていない。** 07-30に「予備校名を出している29記事のうち28本が収益導線ゼロ」と気づいたときと同じ構造で、**導線を置く以前に、カテゴリごと玄関から見えていない。**

評価順2（見つけてもらえる状態に近づくか）に直撃する。しかも**これは執筆も判断も要らない。`index.html` にカードを9枚足すだけである。** 承認さえいただければ今日終わる。

**「確実に合格をもぎ取る」12本について。**

08-07に3本と報告した。今週grepしたら12本あった。**私の報告が過小だった。** 訂正する。

そして12本というのは、**1本ずつ直す種類の問題ではないし、週15本のローテーションで拾う種類の問題でもない。** ローテーションで拾うと、12本を拾い終わるのに数か月かかり、その間サイトには同じ文が残る。**AdSense の審査員は、12本のうち1本を読めば十分である。**

判断：**対応1・2・4をやる。対応3（全記事スキャン）は仕様を書き直したうえでやる。**

## 4. 提案する対応

### 対応1：`.formula` のダークモード対応（🔴 高）

**2つのやり方があり、私は B を推す。**

#### A案：記事3本にローカルの dark 規則を足す

```css
html[data-theme="dark"] .formula{background:#111826;border-color:rgba(140,198,63,.14);color:#CCD6E5}
```

- ○ 影響範囲が3本に閉じる
- ✕ **同じ問題が他の記事にもあれば、その数だけ同じCSSを書くことになる**

#### B案：`article-widgets.js` に `.formula` のダーク背景規則を1つ足す（**推奨**）

```css
html[data-theme="dark"] .formula{background:linear-gradient(180deg,#111826,#0E1421) !important;
                                 border-color:rgba(140,198,63,.14) !important;}
html[data-theme="dark"] .formula{color:#CCD6E5 !important;}
```

- ○ **`.formula` を使う全記事が一度に直る**
- ○ `.mondai` `.point-card` は既に widgets 側でこの形（背景＋文字色をセットで持つ）になっており、**`.formula` だけが片手落ちだった。形を揃えるだけである**
- ✕ 共有ファイルの変更なので、08-04の反省どおり**カンマ区切りセレクタと `!important` の漏れを検算してから入れる**

**あわせて `.ba-item` `.flow-step-body` `.phase-box` `.phase-card` `.step-body` も同じ片手落ちなので、同時に揃える。**

### 対応2：index.html に英検9本のカードリンクを追加（🔴 高・収益/回遊）

対象：`eiken.html` `eiken1.html` `eiken2.html` `eiken3.html` `eiken3-grammar.html` `eiken4.html` `eiken5.html` `eiken-jun1.html` `eiken-jun2.html`

**まず `index.html` に英検カテゴリのセクションが存在するかを目視確認する。**
- 存在する → カードを9枚追加
- 存在しない → **カテゴリセクションごと新設**

あわせて FP3級論点の未掲載4本（`fp3-finance` `fp3-iminai` `fp3-inheritance` `fp3-nannichi`）も同時に処理する。

> **注意：** `eiken.html` と `eiken2.html` はどちらも英検2級を扱っており、カニバリゼーションの疑いが08-07から未解決である（`company/decisions/20260807-*`）。**index に両方載せる前に、統合するか役割を分けるかを決める必要がある。** 決まらない場合は `eiken2.html` のみ掲載し、`eiken.html` は保留とする。

### 対応3：全記事のコントラスト計算スキャン（🔴 高・**08-07仕様を全面改訂**）

**08-07に提案した検出条件は破棄する。** 新しい仕様：

1. 全記事の `<style>` と `article-widgets.js` の**全CSSルールをパースする**
2. `html[data-theme="light"]` / `html[data-theme="dark"]` の**両方について**、各要素に最終的に適用される `color` と `background` を、**詳細度と `!important` を解決して**求める
3. 継承（`<strong>` は親の背景を継ぐ）を考慮する
4. WCAG 2.1 の式でコントラスト比を計算し、**4.5:1 未満を全件リストアップする**
5. `var(--sq-*)` 等の変数は、widgets のテーマ別定義値に展開して計算する

**クラス名・出自・「dark規則の有無」では判定しない。** 3週間で、それらの近道が全部だめだと実証された。

出力は「ファイル / セレクタ / テーマ / 前景色 / 背景色 / 比 / 中身のテキスト先頭30字」の表とする。**中身のテキストを出すのが要点で、潰れているのが装飾なのか答えなのかを人間が5秒で判断できる。**
