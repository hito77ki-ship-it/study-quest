# 【稟議】著者ボックスがh1より上に出るバグの是正（97本）

**起案日：** 2026年7月30日
**ステータス：** ✅ 承認・実行済み
**発見経緯：** 取締役から他サイト（GameWith / Game8）の記事上部のスクリーンショットをご提供いただき、自社記事と見比べた際に発覚

---

## 1. 事象

`article-widgets.js` の `buildAuthorBox()` が、著者プロフィールを**記事タイトル（h1）より上**に挿入していた。

```js
const meta = container.querySelector('.meta');   // ← 最初の .meta を掴む
meta.insertAdjacentElement('afterend', box);
```

記事HTMLの上部はこう並んでいる。

```html
<div class="breadcrumb">TOP > 簿記2級 > 銀行勘定調整表</div>
<p class="meta">日商簿記2級 | 更新日：2026年7月29日</p>   ← querySelector はこれを拾う
<h1>【日商簿記2級】銀行勘定調整表とは？</h1>
<p class="meta">著者：若葉（関西の大学3回生・日商簿記1級勉強中）</p>  ← 本来の意図はこの直後
```

`.meta` が h1 を挟んで2つ存在するため、`querySelector('.meta')`（＝最初の1つ）は更新日の行を掴む。**結果として著者ボックスがh1の直前に挿入される。**

### 影響範囲（全数実測）

| 状態 | 本数 |
|---|---|
| h1の前後に `.meta` がある（著者ボックスがh1の上） | 93本 |
| h1の前だけに `.meta` がある（同じくh1の上） | 4本 |
| **合計：著者ボックスがh1より上** | **97本** |
| h1の後だけに `.meta`（正常） | 103本 |
| 該当なし | 8本 |

### なぜ問題か

1. **読者は記事タイトルを見る前に、著者の自己紹介を読まされる。**「公認会計士試験を約1年半勉強し、現在は日商簿記1級を目標に学習中。…」という4行が、記事が何の話なのか分かる前に来る
2. **著者情報が2箇所で重複している**（著者ボックス＋`p.meta`の著者行）
3. h1より前に記事内容と無関係なテキストが入る

## 2. 参考サイトとの比較（取締役提供のスクリーンショットより）

| | Game8 | GameWith | Study Quest（修正前） |
|---|---|---|---|
| 記事タイトルより上にあるもの | カテゴリタグのみ | ゲーム情報カード・タブ | **著者の長文プロフィール** |
| 日付・著者の表示 | `2026.07.29 17:01 / いっしー` の**1行** | `最終更新：2026年7月30日12:04` のみ | **2箇所に分散** |
| 著者プロフィール | 冒頭に無し | 冒頭に無し | 冒頭に長文 |

**両サイトとも記事タイトルを最優先で見せ、著者情報は1行に抑えている。**

### 学びの方向が逆だった

取締役からは「ブログ記事の上部にいろんな機能が並んでいる」という観点でご提示いただいたが、実測して比べると**Study Questの記事上部は参考サイトより既に機能が多い。**

テーマ切替（System/Light/Dark）・記事検索・CTAボタン・パンくず・カテゴリと更新日・著者ボックス・h1・サブタイトル・著者行・導入会話・指標カード3枚（頻出度/難易度/最重要論点）・左サイドバー（案内板＋おすすめ記事）・右サイドバー（目次＋論点一覧＋学習進捗）。

**足すべきではなく、整理すべき状態だった。** 参考サイトから学ぶべきは機能の追加ではなく、「記事タイトルを最優先に見せる」という順序の規律である。

## 3. 対応

`buildAuthorBox()` の挿入位置決定を、h1との位置関係を見る方式に変更した。

```js
const h1 = container.querySelector('h1');
const metas = Array.from(container.querySelectorAll('.meta'));
let anchor = null;
if(h1){
  anchor = metas.find(m => h1.compareDocumentPosition(m) & Node.DOCUMENT_POSITION_FOLLOWING) || h1;
} else {
  anchor = metas[0];
}
```

`compareDocumentPosition` で「h1より後ろにある `.meta`」を選ぶ。無い場合はh1の直後に挿す。

### 4パターンの挙動

| 記事の構造 | 挿入先 | 判定 |
|---|---|---|
| h1の前後に `.meta`（93本） | h1より後の `.meta` の直後 | ✅ 修正 |
| h1の前だけに `.meta`（4本） | h1の直後 | ✅ 修正 |
| h1の後だけに `.meta`（103本） | 従来と同じ位置 | ✅ 現状維持 |
| h1が無い | `metas[0]` の直後 | ✅ 従来動作を維持 |

**`article-widgets.js` の1箇所を直すだけで97本が同時に直る。記事HTMLは1バイトも触っていない。** `node --check` を通過。

---

## 4. 未対応（意図的に分離）

**著者情報の重複解消は今回やらない。** 著者ボックスと `p.meta` の著者行が同じ情報を出しているが、これを片方に寄せると見た目が変わる。位置バグの修正だけを先に本番へ出し、重複整理は別稟議とする。**1回のリリースで変数を1つに絞る。**

## 6. CEO所見

**このバグは、取締役が他サイトのスクリーンショットを貼ってくださるまで見つからなかった。**

私はこの `article-widgets.js` を今日だけで何度も編集している。著者ボックスを生成する `buildAuthorBox()` のすぐ近くのコードも読んだ。それでも**自分のサイトの記事を1本も「読者として上から順に」見ていなかった。** 見ていれば、タイトルより先に自己紹介が出ることには即座に気づいたはずである。

**コードを読むことと、出力を見ることは別の作業だ。** 今日はこの教訓を、llms.txt（gitignoreに飲まれて本番に無かった）・更新日の73件不一致・PageSpeedのモバイル/デスクトップ取り違えと合わせて4回もらっている。

比較対象を外から持ち込むことの価値も記録しておきたい。自社サイトだけを見ていると「これが普通」に見えてしまう。**Game8とGameWithという他社の並びと突き合わせた瞬間に、異常が浮き上がった。** 定例の記事品質監査に「他社の同種ページと上部の並び順を比べる」工程を入れる価値がある。
