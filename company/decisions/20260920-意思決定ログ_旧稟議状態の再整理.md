# 稟議書：旧稟議の状態再整理と実行キューの分離

**日付：** 2026年9月20日

**決定者：** 取締役承認
**ステータス：** **取締役承認済み（2026年9月20日）**

## 決定

過去の稟議で本文に「取締役の承認待ち」と残る表記を、そのまま実行キューとして扱わない。以後は次の状態を使い、後続の記録がある場合は本稟議の状態表を優先する。

| 状態 | 意味 | 実行の可否 |
|---|---|---|
| 廃止 | 前提・件数・手順が現状と合わず、その稟議のままは実行しない | 不可 |
| 保留 | 価値はあるが、外部条件・一次情報・実体験確認・優先順位待ち | 不可 |
| 重複 | 後続の稟議または承認済みの個別実装に統合済み | 元稟議では不可 |
| 承認待ち | 現時点でも有効で、取締役の判断が必要 | 不可 |
| 承認済み・実装待ち | 決裁は済み、個別の事実確認・実装・検証が残る | 承認範囲内でのみ可 |
| 実装済み・統合待ち | 隔離ブランチで検証・commit済み。ルートのlock解消後も自動統合はしない | 統合判断待ち |

## 運用

1. 今後の監査は、本文中の「承認待ち」検索件数ではなく、この状態区分ごとの件数を報告する。
2. 「廃止」「保留」「重複」は実行リストに入れない。再開時は新しい一次情報と現行記事を確認し、必要なら新規稟議にする。
3. 元稟議の状態行の書き換えは、ルートlock解消後に、1ファイルずつ本稟議の分類と照合して行う。履歴を失わせる一括置換はしない。
4. 記事・図解・UI・外部操作は、この状態再整理だけを根拠に実行しない。
