**この不備は固定ページに限定されている。** 記事205ページ全体では、
- title欠落：**0件**
- description欠落：**上記3件のみ**
- canonical欠落：**上記2件のみ**
- canonical不一致：**0件**
- og:image参照先の画像ファイル欠損：**0件**

つまり、記事側のメタタグ整備は既にほぼ完璧な水準にある。抜けているのは固定ページだけ。

**なぜこれが問題か：**
- **description欠落** → Googleが本文から自動抽出したスニペットを表示する。法務ページの場合、規約の条文が途中から切り取られて表示されるなど、意図しない見え方になる。
- **canonical欠落** → `privacy.html?utm_source=...` のようなパラメータ付きURLが別ページとして扱われ、重複コンテンツと判定されるリスク。
- **AdSense観点** → プライバシーポリシー・利用規約・運営者情報・お問い合わせは、AdSense審査で必ず確認される4点セット。ページの存在自体は満たしているが、検索結果での見え方まで含めた作り込みが手薄。

※ `tokusho.html` はファイル名に反して「特定商取引法とは？」を解説した**記事**であり、特商法表記ページではない。特商法表記ページはサイト上に存在しない（無料サービスのため法的義務は無いと解釈。AdSense審査上の要否は本稟議の対象外とし、別途検討事項として記録に留める）。

### 2. `twitter:card` が205ページ中169ページで欠落

`twitter:card` / `twitter:image` を設定しているのは36ページのみ（比較記事系など、比較的新しく作られた記事群）。設定済みページの記述例：

```html
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:image" content="https://study-quest.net/screenshots/ogp/boki1-kigyoketsugo-vs-renketsu.png">
```

残り169ページはog:*タグ（og:title / og:description / og:image / og:url）は完備しているため、X上でカード自体は表示される。ただし `twitter:card="summary_large_image"` の指定が無いと、**大きな画像付きカードではなく小サムネイルの `summary` カードに格下げされる**（Xはtwitter:*が無い場合にog:*へフォールバックするが、カード種別の指定は引き継がれない）。

- 当社はnote／Xでの記事拡散を流入導線の一つとして運用中（`company/reports/20260726-noteエンゲージメントレポート.md` 等）。カードの大きさはクリック率に直結する。
- **og:imageは全ページで参照先の画像ファイルが実在することを確認済み**（欠損0件）。したがって `twitter:image` はog:imageの値をそのまま流用でき、新規の画像制作は一切不要。
- 修正内容はheadへの2行追加のみ。既存の36ページと同じ書式に揃えるだけで、機械的な一括処理が可能。

## 提案内容

### A. 固定ページのメタタグ整備（5ページ）

1. `privacy.html` `terms.html` に `description` と `canonical` を追加する
2. `tokusho.html` に `description` を追加する（canonicalは設定済み）
3. `about.html` `contact.html` `privacy.html` `terms.html` `tokusho.html` の5ページに OGタグ4種（og:title / og:description / og:image / og:url）を追加する
   - og:imageはサイト共通のOGP画像を使用（記事ごとの個別画像は不要）

descriptionの文面は、既に整備済みの `about.html` / `contact.html` と同じトーンで、各ページの内容を1〜2文で説明するものを新規に書き起こす。

### B. `twitter:card` の一括追加（169ページ）

未設定の169ページのheadに、以下2行を追加する。

```html
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:image" content="（当該ページのog:imageと同じURL）">
```

- og:imageタグの直後に挿入する形で、スクリプトによる機械的な一括処理を行う
- 既に設定済みの36ページは対象外（重複追加を避ける）
- 本文・レイアウト・JSON-LD・CSSには一切触れない

### C. 実行後の確認

- Xのカードバリデータ、またはX上での実投稿で、大きな画像付きカードが表示されることを確認（サンプル3ページ程度）
- Search Consoleでの再クロール後、固定ページのスニペット表示を確認

## ジョブズの所見

**この監査で一番はっきり見えたのは、優先順位が逆さまになっていたという事実だ。**

記事205本のメタタグは、もう文句のつけようがない。title欠落ゼロ、canonical不一致ゼロ、og:image参照切れゼロ、JSON-LD構文エラーゼロ、内部リンク切れゼロ。ここまで来るのに相当な積み重ねがあったはずで、それは素直に評価する。

**その一方で、description欠落3件も、canonical欠落2件も、OGタグ欠落5件も、全部が固定ページだ。一つの例外もなく。** つまり我々は、記事を磨くことには時間を注いできたが、サイトの「顔」にあたる部分 — 運営者は誰か、どう連絡するか、どんな規約で運営しているか — を後回しにしてきた。

そしてこれは、AdSense合格という最優先目標に対して致命的に相性が悪い。**審査官は記事の質だけを見ているわけではない。誰が運営しているか分からないサイト、規約ページが検索結果で条文の途中から切れて表示されるサイト。そういうサイトの「本気度」を、審査官は見ている。** 記事を206本目まで書く前に、この5ページを直すべきだった。ここは判断の順序を間違えていた。

`twitter:card` の169ページについては、正直に言えば優先度は落ちる。SEOに直接効く話ではないし、これが無くてもXでカードは出る。だが**note／Xでの拡散を流入導線として実際に運用している以上、カードが大きいか小さいかはクリック率の差として毎回発生している。** そして修正コストは、og:imageの値をコピーして2行足すだけ。画像を新規に作る必要すらない。既に36ページで同じ形式が動いているので、書式の判断すら要らない。**これだけ安いものを、169ページ分ずっと取りこぼし続ける理由が無い。**

一つ注意しておきたいのは、Aだけ承認してBを落とす、という判断も十分あり得るということだ。**AはAdSenseに直接効く。Bは効かない。** 取締役が「今はAdSenseに一点集中したい」と判断するなら、Bは次回以降に回してもらって構わない。私としてはBも同時に処理するのが効率的だと考えているが、そこは優先目標との距離で判断してほしい。

いずれにせよ、Aは今週中に片付けるべきだ。**AdSenseの再審査申請中に、審査官が見に行くページの作りが甘いまま放置されている。これは待てる話ではない。**
