# 運用方針：実行専用タスクを毎日実行する

**日付：** 2026年8月30日（`git log -1 --date=iso`で確認）
**決定者：** 取締役（会話での指示）／CEOジョブズ
**種別：** 自動実行の運用方針
**ステータス：** 採用・設定可能になり次第適用

## 決定内容

包括実行委任（2026-08-30）の実行専用タスクは、週2回ではなく**毎日1回**起動する。

ただし、1回の実行で処理するのは**最大1案件**とする。対象案件が無い、または検証条件を一つでも満たさない場合は、ファイル・外部サービス・GitHubに変更を加えず、実行しなかった理由だけを記録して終了する。

## 対象条件

実行できるのは、次をすべて満たすキュー登録済み案件だけである。

1. 稟議・根拠・具体的な変更範囲が記録済みである。
2. 低リスクかつ機械検証可能である。
3. 隔離cloneで1案件1PRに分離できる。
4. `git diff --check`、対象に応じた構文・リンク・差分検証が成功する。
5. 最新`main`と競合せず、無関係な差分を含まない。

UI・デザイン、記事の新規執筆／大幅リライト、note・Xを含む外部送信、広告・AdSense、契約・支出、個人情報、規約・同意は対象外とする。毎日実行に変えても、この境界は緩めない。

## 実行の順序

1. キューの先頭から適格な1案件だけを選ぶ。
2. 隔離cloneで変更・検証・PR作成を行う。
3. PRがクリーンで、必須検証が成功した場合だけ自動マージする。
4. PR番号、マージコミット、検証結果、または停止理由をレポートに残す。

毎日回す目的は、待ち行列を早く処理することであり、1日に多くの変更を入れることではない。

## 実装上の留保

この環境では、実行専用の定期タスクを新規作成・編集する操作が現在提供されていない。そのため本決定は運用仕様を先に確定するものであり、実際のスケジュール作成は設定機能が利用可能になった時点で行う。

## ジョブズの所見

実行が週2回では、検証済みの小さな改善まで滞留する。毎日1件に制限すれば速度を上げつつ、原因追跡とロールバックの単位を保てる。自動化の価値は件数ではなく、人が待たなくても安全に前進できることにある。
