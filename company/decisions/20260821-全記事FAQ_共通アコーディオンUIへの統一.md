# 稟議書：全記事FAQを共通アコーディオンUIへ統一する

**起案日：** 2026年8月21日
**起案者：** CEO ジョブズ
**ステータス：** **取締役承認済み**（取締役の「そうですねやりましょう」という明示指示にもとづく）

## 本稟議の指摘は 1 件

FAQを画面に持つ記事では、質問が灰色の帯・本文・既存の`details`など複数の表示形式に分かれ、質問が押せる見た目なのに開閉しない記事もある。

全HTMLを走査した結果、`FAQPage`構造化データを持つページは192本、そのうち画面に`.faq-item`を持つページは80本だった。内訳は記事79本と、別UIを持つトップページ1本である。今回の対象は、読者が実際に操作する**79本の記事の表示FAQ**である。構造化データのみで、画面上のFAQを持たないページには本文を新設しない。

## 決定

1. 共通の`article-widgets.js`で、既存のFAQ質問をキーボード操作可能なボタンまたは`details`に統一する。
2. 各FAQは最初の1件だけを開いた状態にし、別の質問を開くと前の回答を閉じる。長文記事の末尾を必要以上に伸ばさない。
3. 深紺の面・ライムの一点アクセント・硬質な枠線を使い、Dark Mode Digital / Field Systemとテーマ切替に追従させる。
4. 本文、質問文、回答文、FAQPageの構造化データ、記事の日付、広告配置は変更しない。対象外の記事へFAQ本文を自動生成しない。

## 検証

- 80本の表示FAQを機械的に検出し、質問と回答の対応漏れがないことを確認する。
- 代表3形式（`h3 + .faq-answer`、`.faq-q + .faq-a`、既存`details`）をPC幅・390px幅、ライト・ダークで確認する。
- キーボードのTab/Enter操作、`aria-expanded`、回答の開閉、`prefers-reduced-motion`を確認する。
- UI共通変更は独立ブランチでcommit/pushし、既存の未コミット変更や他の公開単位と混ぜない。

**「それはユーザーの人生を本当に変えるか？」**

質問と答えの境目を明確にし、知りたい1点へ素早く到達できるようにすることで、読者が記事末尾で迷わず復習へ戻れるようにする。
