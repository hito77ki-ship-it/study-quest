## 2. 問題A-1：boki3-credit.html — 記事が最も強調している箇所で仕訳の貸借が逆

### 該当箇所（173行目）

```html
<div class="warn-box"><strong>【最大のひっかけ】売上は満額・クレジット売掛金は手数料控除後</strong><br>
売上は販売価格の満額で計上します。クレジット売掛金（信販会社に対する債権）は手数料を差し引いた金額になります。
この「売上とクレジット売掛金の金額が違う」ことが最大の落とし穴です。<br>
例）売上10,000円・手数料200円 → 売上 10,000 ／ クレジット売掛金 9,800 ＋ 支払手数料 200</div>
```

### 問題1：貸借が逆転している

本サイトは記事全体を通じて「A ／ B」を「**借方A ／ 貸方B**」の意味で使っている。同じ `boki3-credit.html` 内の他の仕訳、および `boki3-denpyo.html` の「現金 20,000 ／ 売上 20,000」「買掛金 10,000 ／ 現金 10,000」など、サイト内で例外なくこの記法である。

この記法に照らすと、上記は「借方：売上10,000 ／ 貸方：クレジット売掛金9,800・支払手数料200」を意味する。**売上（収益）が借方に、クレジット売掛金（資産）と支払手数料（費用）が貸方に置かれており、3科目すべてが逆である。**

正しくは：

```
クレジット売掛金 9,800 ＋ 支払手数料 200 ／ 売上 10,000
```

### 問題2：数値が本文の例題と一致しない

本記事の例題は一貫して「商品10,000円・手数料率3%＝300円 → クレジット売掛金 9,700円」である（200・210・224・227・229・237・240・242・252行目のすべて）。この warn-box だけが手数料200円・9,800円になっている。**同じ「10,000円の販売」に対して2組の数字が並んでおり、読者はどちらが正しいか判断できない。**

CLAUDE.md 定型チェック項目14（同一記事内の数値整合）に該当する。

## 3. 問題A-2：article-widgets.js — カンマ区切りセレクタ6箇所でテーマ限定が外れ、ライトモードが壊れている

### なぜ壊れるか

CSS のカンマ区切りセレクタは、各要素が完全に独立したセレクタとして扱われる。祖先条件は左側から自動的に引き継がれない。したがって：

- `html[data-theme="dark"] .hc-row.hc-total .hc-label` → ダークモードのみ
- `.hc-row.hc-total .hc-amt` → **テーマに関係なく常時適用**

`.hc-amt` / `.zc-amt` は**金額欄**である。ダークモード用の明るい文字色が、ライトモードの明るい背景の上に `!important` で強制される。

## 4. ファクトチェック

### 4-1. クレジット売掛金の正しい処理（A-1）

日商簿記3級の出題範囲におけるクレジット売掛金の販売時仕訳は、**手数料を販売時に計上する方式**の場合：

```
（借）クレジット売掛金 9,800    （貸）売上 10,000
（借）支払手数料          200
```

- 売上は**販売価格の総額**（10,000円）で計上する
- クレジット売掛金は信販会社に対する債権であり、**手数料控除後の入金予定額**（9,800円）
- 支払手数料は費用（借方）

記事本文の解説文「売上は販売価格の満額で計上します。クレジット売掛金は手数料を差し引いた金額になります」は**正しい**。誤っているのは、その直後の例示の並べ方だけである。つまり内容を理解していないのではなく、**記法の適用を誤った**種類のミスである。

なお本文の例題（200〜252行目、手数料率3%）の仕訳は借方・貸方とも正しく、`.kari` / `.kashi` クラスで正しくマークアップされている。**warn-box だけが平文で書かれており、そこで逆転している。**

### 4-2. CSS カンマ区切りセレクタの仕様（A-2）

W3C Selectors Level 3 / CSS Cascading and Inheritance の規定により、セレクタリスト（カンマ区切り）の各セレクタは独立して評価される。左側のセレクタの祖先条件は右側に引き継がれない。これは仕様どおりの挙動であり、ブラウザ差はない。

同種の欠陥がないか `article-widgets.js` 全体を機械的に検算したところ、**テーマ限定が外れているカンマ区切りセレクタは上記6箇所のみ**だった（全 `[data-theme]` ルールを対象に走査）。

### 4-3. WCAG コントラスト基準

WCAG 2.1 達成基準 1.4.3（レベルAA）：通常サイズのテキストは 4.5:1 以上、大きなテキスト（18pt以上または14pt太字以上）は 3:1 以上。今回の `.hc-amt` / `.zc-amt` は 13px・font-weight:700 で、大きなテキストの定義には該当しないため 4.5:1 が適用される。

## 5. CEOジョブズの所見

**A-2 は、私がこれまでやってきた監査の設計が間違っていたことの証拠である。**

07-30 に「記事ファイル単位の監査だけでは見つからない構造欠陥がある」と書き、`ARTICLES` の両方向検算を定型項目に入れた。だがそれは**登録漏れ**という「無い」ことを探す検算だった。今回のは違う。`article-widgets.js` に**書いてあるコードそのものが間違っていた**。共有ファイルを検算対象にしていなかったから、7月中の4回の監査を素通りしている。

そして潰れていたのは**ライトモードだ**。ダークモードの不具合なら「トグルを切り替えた一部のユーザーだけ」で済む。ライトモードは既定である。**訪問者の大半が、消費税の例題の答えが見えない状態のページを見ていた。** どれだけの人が「この記事は数字が抜けている」と思って離脱したかは分からない。分からないことが問題だ。

**A-1 はもっと直接的だ。** boki3-credit.html は4,186字あり、例題も3問あり、会話セクションもあり、リンク切れもない。「薄い記事を探す」監査では100%引っかからない。引っかかったのは、記事内の同じ取引の数字を全部並べたからだ。そして出てきたのが、記事自身が「**【最大のひっかけ】**」と名指しで強調した1文の中の、3科目すべての貸借逆転だった。

**読者が一番信用して読む場所が、一番間違っていた。** これは確率の問題ではない。強調ボックスは「ここだけは覚えて帰ってください」という宣言である。そこに誤りを置くのは、他のどこに誤りを置くより悪い。

判定基準に照らす。

1. **収益に直結するか** — 直接の導線ではない。だが `boki3-credit.html` も `boki3-shohi.html` も `boki3-kabushiki.html` も簿記3級の主要論点記事で、簿記3級の読者は2級・1級へ進む導線の入口にいる。**「このサイトは仕訳の貸借が逆」「数字が見えない」と思われたら、その先の予備校アフィリエイトは絶対に成立しない。** 信頼の問題であり、収益の前提である。
2. **見つけてもらえる状態に近づくか** — コアウェブバイタルやアクセシビリティは直接の順位要因ではないが、**内容の誤りは E-E-A-T の「信頼性」に直結する**。加えて、答えが読めないページの滞在時間・離脱率は確実に悪い。
3. **ユーザーの人生を本当に変えるか** — 変える。ただし**悪い方向に**。貸借を逆に覚えた読者は試験で落ちる。これは「役に立たない」ではなく「害がある」レベルである。

07-31 に金額のルールを作ったとき、私はこう書いた。「**その状態で数字が間違っているのは、品質の問題ではなく信義の問題である。**」今回も同じことを言う。**貸借が逆なのは品質の問題ではない。信義の問題である。**

**シンプルさは究極の洗練である**——ならば、直し方も単純であるべきだ。A-1 は1行を書き直すだけ。A-2 は6箇所にセレクタを補うだけ。難しい判断は何もない。**難しかったのは見つけることだけで、それはもう終わっている。**

## 6. 提案する対応

### 対応1：boki3-credit.html の warn-box を修正（A-1）

173行目の例示を、貸借を正し、本文の例題（手数料率3%・300円）と数値を揃える。

**修正前：**
```
例）売上10,000円・手数料200円 → 売上 10,000 ／ クレジット売掛金 9,800 ＋ 支払手数料 200
```

**修正後（案）：**
```
例）販売価格10,000円・手数料300円（3%）
→ クレジット売掛金 9,700 ＋ 支払手数料 300 ／ 売上 10,000
```

あわせて、本文の他の仕訳と同じ `.shiwake-box` / `.kari` / `.kashi` マークアップを使う形に揃えることを推奨する（平文で書いたことが逆転を生んだ直接の原因であるため）。ただしこれは任意とし、**最低限、貸借と数値を正すだけでも承認いただきたい**。

### 対応2：article-widgets.js の6箇所にテーマ限定を補う（A-2）

**修正前（1393行目の例）：**
```css
html[data-theme="dark"] .hc-row.hc-total .hc-label,.hc-row.hc-total .hc-amt{color:#C4B5FD !important;}
```

**修正後：**
```css
html[data-theme="dark"] .hc-row.hc-total .hc-label,
html[data-theme="dark"] .hc-row.hc-total .hc-amt{color:#C4B5FD !important;}
```

1393・1395・1397・1407・1409・1411 の6行に同じ処置を行う。

**リスク：** 極めて低い。付け足すのは祖先条件のみで、ダークモード時の挙動は一切変わらない。ライトモード時に**本来の記事側の色指定が復活する**だけである（`boki3-kabushiki.html` 85〜87行目、`boki3-shohi.html` 87〜89行目に定義済み）。

### 対応3：更新日の同時更新

CLAUDE.md「更新日を変更するときのルール」に従い、`boki3-credit.html` の JSON-LD `dateModified` と本文「更新日」表示を**2箇所セットで** 2026-08-04 に更新する。

`boki3-kabushiki.html` `boki3-shohi.html` は記事ファイル自体を編集しないため、日付は更新しない（`article-widgets.js` の修正は記事内容の変更ではない）。

### 対応4（同時処理・軽微）

本稟議の作業ついでに処理してよい軽微項目：

- `boki3-credit.html` の未使用CSS `.lead` を削除
- `boki3-credit.html` の関連記事リンクをルート相対（`/boki3-kake.html` 等）から相対（`boki3-kake.html`）に統一
- `boki3-credit.html` の `.hikaku-table .row-credit td`（背景 #EBF8FF）にダークモード対応を追加
