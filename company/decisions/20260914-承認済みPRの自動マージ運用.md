# 稟議書：承認済みPRの自動マージ運用

**起票日：** 2026-09-14
**起票者：** CEO ジョブズ
**ステータス：** 取締役承認済み（2026-09-14、チャットで「マージしていないやつらは、勝手に自動で、マージしていいよ今後も」と承認）
**種別：** 公開運用プロセスの変更

---

## 1. 承認範囲

`hito77ki-ship-it/study-quest` の、`main` 向けかつ `codex/` ブランチからのPRを対象に、条件をすべて満たす場合だけ自動マージを認める。

これは `20260914-定期自動化を監査と判断支援へ再設計.md` の「自動マージをしない」を、**承認済みPRのマージ操作に限って**置き換えるものである。記事・UIを含む変更の承認手順、隔離cloneでの実装、1案件1コミット、push先確認は置き換えない。

## 2. 自動マージの必須条件

1. PRはdraftでなく、baseが `main`、headが `codex/` で始まる。
2. `main` との競合がない。
3. 必須チェックがすべて成功している（意図的なskipは可）。
4. 変更内容、PR本文、または対応する稟議から、取締役承認・根拠・検証の証跡を確認できる。
5. 記事本文・図解・UIの変更では、ファクトチェック→稟議→取締役承認→実装→実施報告→検証が明示されている。

1件でも欠けるPRは自動マージしない。理由を報告して人の判断を待つ。

## 3. 自動マージの対象外

- AdSense再申請、GSC再送信、広告設定、外部アカウント設定
- SNS・Noteなどの外部送信
- `main` への直接push、force操作、PR作成、commit、push、ブランチ削除
- 競合、必須チェック失敗・待機、承認証跡不足のPR

## 4. 実行上限と検証

- 1回の定期実行でマージするのは最大3PRとする。
- 実行後にPR番号、merge commit、必須チェック、承認根拠を記録する。
- 自動化健全性監査は週次で、この条件と実行結果を検算する。
