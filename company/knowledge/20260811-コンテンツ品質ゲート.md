# コンテンツ品質ゲート

## 目的

記事を増やす前に、読者へ誤った判断材料を届ける事故と、読めない表示を公開前に止める。自動化の役割は検出と証拠の整理であり、記事本文・制度数値・公開ページの自動変更ではない。

## 実行コマンド

```bash
node scripts/audits/run-content-quality-gate.mjs
```

個別確認では次を使う。

```bash
node scripts/audits/run-content-quality-gate.mjs --paths fe.html,fe-vs-ap.html,itp-vs-fe.html --no-write
```

`--strict` は、h1・JSON-LD・ローカルリンク切れがあると終了コード2を返す。更新日・制度数値・配色は、人間の一次情報照合や実画面確認が必要なため、通常はレポート候補として扱う。

## 固定した検査条件

| 区分 | 検査 | 判定 |
|---|---|---|
| 構造 | Articleのh1が1つ、JSON-LDが構文正しい | 破綻なら公開停止候補 |
| 導線 | root HTMLへのローカルリンク先が存在する | 切れなら公開停止候補 |
| 鮮度 | JSON-LD・本文表示・sitemapの更新日が一致する | 不一致なら修正候補 |
| 数値 | 同じ読者向け主張の数値表現を横断比較する | 一次情報照合候補 |
| 配色 | 白背景とテーマ追従文字色の組み合わせでdark上書きが見つからないものを抽出する | 実画面確認候補 |

## 運用原則

1. 構造エラーは、正しさを解釈せず機械的に止める。
2. 制度数値の候補は、検出器の出力を正解として書き戻さない。必ず主催団体・省庁などの一次情報を使う。
3. 色の候補は、DOMの最終適用値がCSSの順序に左右されるため、ライト・ダーク両方の実画面確認を経る。
4. 事実誤りは `CLAUDE.md` の例外に従って即時是正できるが、構成・説明・デザインの変更は稟議を分ける。
5. 監査結果は `company/reports/automation/` に日付付きで保存し、記事変更の根拠と混ぜない。
