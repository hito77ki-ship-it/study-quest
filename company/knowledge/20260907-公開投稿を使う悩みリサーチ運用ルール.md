# 公開投稿を使う悩みリサーチ運用ルール

**作成日：** 2026年9月7日
**対象：** Study Quest の記事企画・既存記事監査に使う、公開検索結果、公開 Q&A、公開動画コメント等
**目的：** 読者がどの言葉で迷い、次に何を決められずにいるかを見つける。制度・数値・採用結果などの事実を立証する用途には使わない。

## 1. 役割を分ける

| 区分 | 使ってよいこと | 使わないこと |
|---|---|---|
| 悩みリサーチ | 検索語、迷いの種類、記事で解くべき判断を仮説にする | 「多くの人が困っている」「この選択なら有利」などの一般化 |
| ファクトチェック | 官公庁、試験実施団体、募集元などの一次情報を実際に開き、本文に出典リンクを置く | 投稿や検索要約を根拠に、日程・費用・受験資格・選考結果を書く |
| 記事本文 | 仮説を、読者が自分の記録と公式情報を照合できる手順に変える | 投稿文の転載、個人の体験をサイトの体験談として扱うこと |

公開投稿は「何を確認したい読者がいるか」を示す観察材料であり、頻度・因果・正解を示す統計ではない。記事では「投稿で見たから」ではなく、公式情報と読者自身の記録を判断の根拠にする。

## 2. 取得・保存の最小化

- 公開され、ログインや有料契約を回避せずに読めるページだけを見る。規約や robots.txt を回避するスクレイピングはしない。
- X など取得条件が不明確なサービスは、公式 API と利用規約を確認できるまで自動収集しない。ブラウザで偶然見た投稿も、本文を保存しない。
- YouTube は API キーを取得するまで、検索結果や動画説明欄など公開範囲の手作業確認に留める。コメントの一括収集はしない。
- 保存するのは、検索語、確認日、媒体種別、匿名化した悩みの要約、企画上の仮説、公開 URL のみとする。投稿本文、スクリーンショット、アカウント名、ハンドル、プロフィール、投稿者を特定できる引用は保存しない。
- URL に投稿者識別子が含まれる場合も、調査記録での参照に限定し、記事本文・画像・構造化データへ転載しない。
- 健康状態、障害、生活苦、未成年に関する個人的な記述は、企画材料としても保存・分類しない。緊急性が疑われる記述を見つけても診断や助言記事の根拠にせず、医療・相談窓口の一次情報を別途確認する。

## 3. 記録フォーマット

| 項目 | 記録する内容 |
|---|---|
| 検索語 | 実際に入力した語句 |
| 確認日 | 調査日 |
| 媒体種別 | 公開 Q&A、個人記事、専門家記事、公式情報など |
| 悩みの要約 | 固有名詞・原文引用を除いた一文の要約 |
| 仮説 | 記事が解くべき判断。頻度の主張はしない |
| 既存資産との重複 | 既存記事・稟議との重なりと、作らない判断 |
| 公開 URL | 検証用。記事には転載しない |
| 公開前に必要な一次情報 | 制度・数字・日程の根拠として確認すべき発行元ページ |

同じ論点が複数の公開ページに現れても、件数を母数として扱わない。検索順位、媒体の編集方針、宣伝目的、アルゴリズムの影響があるためである。

## 4. 記事企画へ進める条件

次のすべてを満たしたときだけ、別の稟議で記事企画を起案する。

1. 既存記事・承認済み稟議との重複を確認し、読者の現在地または出口が異なる。
2. 読者が自分で確認できる一次情報または記録に、結論を接続できる。
3. 選考の有利不利、年収、合格、学習時間、将来性を断定しない構成にできる。
4. 投稿の要約なしでも、独自の判断表・照合手順・既存記事への行き先を提供できる。
5. 記事本文・図解・UIを変える場合は、ファクトチェック、稟議、実施報告、対象検証を別途行う。

## 5. API を使う段階になったら

API キーはリポジトリ、記事、チャットに記載しない。環境変数または利用サービスのシークレット管理に置き、対象 API を限定し、利用規約・割当量・保存期間を確認してから、収集量を最小にした試行を別タスクとして起案する。このルールだけでは API 利用を承認しない。
