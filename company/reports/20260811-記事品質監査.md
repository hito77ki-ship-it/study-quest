### 🔴 高：ダークモードの可読性（観点③）— **新種の破綻パターン**

`.formula` クラスで、ダークモード時の文字コントラストが **1.01:1**（WCAG AA基準 4.5:1）まで落ちる。

| ファイル | `.formula` 内の `<strong>` | 内容 |
|---|---|---|
| fp3-finance.html | 4箇所 | PER「10倍」「1倍」「25倍」等 — **計算の答え** |
| fp3-nannichi.html | 3箇所 | 「①今日の日付を確認」「②60日後を仮の受検日に設定」「③テストセンターの空き状況…」 — **逆算3ステップの手順そのもの** |
| fp3-lifeplanning.html | 1箇所 | 「約27.4万円/年」 — **減債基金係数の計算結果** |

**原因は、これまで見てきたどのパターンとも違う。**

```
記事側:   .formula{background:#F7F9FF; ... color:#374151}   ← 明るい背景を固定
widgets:  html[data-theme="dark"] .formula strong{color:#F8FAFC !important;}  ← 文字を白に強制
widgets:  html[data-theme="dark"] .formula{...}  ← 存在しない（背景を暗くする規則が無い）
```

結果、ダークモードで **#F8FAFC（ほぼ白）の文字が #F7F9FF（ほぼ白）の背景に載る。**

> **08-07に立てた仮説「widgets が名前を知っているクラスは無傷、独自クラス名だけが壊れる」は、反証された。** `.formula` は widgets が名前を知っているクラスである。にもかかわらず壊れる。理由は、widgets の `.formula` 対応が**`strong` の文字色だけで、背景を持っていない**から。**名前を知っているかどうかではなく、「文字色と背景の両方を面倒みているか」が分かれ目だった。**

**同型リスクを持つクラスを widgets 全体からスキャンした。** ダークモードで `strong` を `#F8FAFC` に強制するのに、同じクラスのダーク背景規則を持たないもの：

```
.ba-item / .flow-step-body / .phase-box / .phase-card / .step-body / body
```

今回の15本ではこれらは使われていないが、**全記事スキャンが必要**（稟議 対応3）。

## 6. CEOの所見

**今週は、ようやく「直った」ものが確認できた回である。**

`eiken2.html` は08-07に指摘した2024年度リニューアル未反映が08-10に修正されていた。ARTICLES 未登録は15本中0本で、07-31から4週続いていた項目が初めてゼロになった。**発見だけが積み上がる状態からは半歩抜けた。**

ただし、抜けきってはいない。

**第一に、`eiken3.html` の取りこぼしは私の分類ミスである。** 08-07に英検6本を横断調査したとき、「Eメール問題に言及があるか」で反映済み／未反映を仕分けた。`eiken3.html` は言及があったので反映済みに入れた。実際には**試験時間が旧値のまま、ライティング解説が1題ぶんしかない**という部分反映だった。制度改正の追随は二値で判定してはいけない。**改正で変わった項目を列挙して、1項目ずつ突き合わせる。**

**第二に、`.formula` の破綻は、私が先週立てた仮説を反証した。** 08-07に「壊れるのは独自クラス名だけ」と書き、機械検査の条件まで具体化した。**その条件では今週の8箇所は1つも検出できない。** widgets が名前を知っていて、しかも `strong` の色だけ面倒を見て背景を見ていない、という第三のパターンだった。仮説を出した翌週に反例が出るのは悪いことではない。**悪いのは、仮説を検査条件に固めたまま全記事スキャンを走らせることである。** 稟議 対応3の仕様は書き直した。
