# 成果保証・最上級表現の監査検出器 実装報告

## 実施日

2026年8月25日

## 目的

全公開記事を自動で書き換えず、合格・得点・理解などの結果を断定する表現と、根拠を確認する必要がある最上級・煽り表現を、編集前の候補として一覧化する。2026年8月26日付の稟議で見つかった表現を、今後の監査で取りこぼさないための仕組み化である。

## 実装内容

- `scripts/audits/run-claim-language-audit.mjs` を追加した。
- ルート直下のArticleページを対象に、本文から成果保証候補と最上級・煽り候補を抽出する。
- 標準出力と `company/reports/automation/YYYYMMDD-claim-language-audit.md` に候補を記録する。
- `--paths` で対象記事を絞り、`--no-write` でファイルを保存せず確認できる。
- 検出器は記事・サイトマップ・ウィジェットを変更しない。候補の一括置換もしない。

## 検証

```bash
node --check scripts/audits/run-claim-language-audit.mjs
AUDIT_DATE=20260825 node scripts/audits/run-claim-language-audit.mjs \
  --paths boki3-next-exam.html,boki3-kashidaore.html \
  --output-dir tmp/claim-audit
AUDIT_DATE=20260825 node scripts/audits/run-claim-language-audit.mjs --no-write
git diff --check
```

- 構文チェック: 成功
- 既知候補（試験日記事3件・貸倒記事2件）: 5件を検出
- 全Article監査: 128記事中128記事に候補（成果保証78件、最上級・煽り347件）
- `git diff --check`: 成功

全件の結果は候補であり、ポリシー違反や誤りの件数ではない。例えば公式事実、学習手順、否定表現も文脈確認が必要な候補に含まれうる。修正は、記事ごとの一次情報確認と稟議・事実是正ルールに従って別PRで行う。
