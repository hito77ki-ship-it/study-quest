# 端末内パーソナライズ推薦（第1段階）実施報告

**実施日：** 2026年8月12日
**担当：** CEO ジョブズ
**対応する稟議：** [端末内パーソナライズ推薦（第1段階）](../decisions/20260812-端末内パーソナライズ推薦_第1段階.md)

## 実装方針

各記事の末尾に「あなたにおすすめの記事」を表示する。推薦はブラウザーの`localStorage`だけで計算し、サーバーへ閲覧傾向を送信しない。

| 信号 | 扱い |
|---|---|
| 記事を開く | 直近のテーマとして軽く反映 |
| 既存の読了マーク | 同じテーマへの関心として強めに反映 |
| リアクション | 成功して選択済みになった場合だけ、強めに反映 |
| 推薦カードのクリック | 次の興味として端末内へ反映 |

## 表示

- 現在の記事と最近読んだ記事は候補から外す。
- 履歴が少ない間は編集部が確認した入口記事を出し、2記事以上の傾向があれば「最近読んだテーマに近い記事」として理由を添える。
- デスクトップは3列カード、モバイルはサムネイル左・タイトル右の横長カードにする。
- 履歴の消去ボタンと「外部には送信しない」説明を表示する。

## 検証

| 項目 | 結果 |
|---|---|
| JS構文・差分空白検査 | 正常 |
| 簿記の履歴 | `boki2-next-exam`、`boki-careless-miss`、`boki-zasetsu-type` を優先 |
| ITの履歴 | `ap`、`fe-vs-ap`、`mos` を優先 |
| 英語の履歴 | `eiken1`、`toefl`、`ielts` を優先 |
| 実画面 | 見出し、3カード、推薦理由、履歴消去、プライバシー説明を確認 |
| 横はみ出し・ブラウザーエラー | 0件 |

ブラウザーの検証環境では端末ストレージの中身を直接扱わず、推薦分岐は擬似履歴を使うロジックテストで確認した。実運用では標準の`localStorage`にだけ保存する。

## 次の判断

閲覧・読了・関連記事クリックの変化を見てから候補数や分類を増やす。端末をまたぐ同期、ログイン情報との結合、閲覧数を使う人気順の混合はこの段階では行わない。
