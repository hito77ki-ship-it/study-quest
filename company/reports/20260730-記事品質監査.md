## ③ 表示バグ（コードから断定できるもの）

### ③-1 `boki2-kogyo-enshu.html`：ダークモードで論点リンクカード12枚が読めない

**該当箇所：** 27行目の `<style>` 内 `.topic-link-card`、および73〜120行のマークアップ

```css
.topic-link-card{ ... background:#fff; ... color:inherit; ... }
```

```html
<a class="topic-link-card" href="boki2-kogyo.html">
  <div style="...color:#1A202C;">工業簿記とは？商業簿記との違い</div>
  <div style="...color:#718096;">まず全体像をつかむ。勘定の流れ・費目の分類を一気に理解</div>
</a>
```

`article-widgets.js` のダークモード救済網は**インライン `style` 属性しか見ていない**：

```css
/* 869行 */ html[data-theme="dark"] .container [style*="background:#fff"]{ background:linear-gradient(...) !important; }
/* 897行 */ html[data-theme="dark"] .container [style*="color:#1A202C"],
/* 901行 */ html[data-theme="dark"] .container [style*="color:#718096"]{ color:#CCD6E5 !important; }
```

- カード背景 `#fff` は**クラス定義**なので869行の網に掛からず、白のまま残る
- カード内テキストは**インライン**なので897〜907行が効き、`#CCD6E5` に置換される

**結果：白 `#fff` 背景に `#CCD6E5` の文字 → コントラスト比 1.47:1。** WCAG 2.2 AA の本文基準 4.5:1 を大幅に下回る。該当は工業簿記の論点リンクカード12枚（=この記事の本体）。`.topic-link-card` はこの記事にしか存在せず、widgets 側にもダークモード定義がない。

なお同じパターン（クラス指定の白背景）を全15本で走査したが、`.point-card` は widgets にダークモード定義があるため無害で、**問題は `.topic-link-card` のみ**だった。

### ③-2 `boki2-hojinzei-shohizei.html` / `boki2-junshisan.html`：効かないCSSと死にコード

```css
.td-total{ font-weight:700; background:#E8F7B8 !important; }
.td-minus{ color:#C05621; font-weight:700; }
```

- **`.td-total` / `.td-minus` / `.td-r` はマークアップで一度も使われていない**（`<style>` 内の定義のみ、両ファイルとも）
- `.td-minus`（詳細度 0,1,0）は widgets の `html[data-theme="light"] td{color:#2D3748}` / `html[data-theme="dark"] td{color:#CCD6E5}`（0,1,1）に負けるため、**仮に使っても橙色は出ない**
- `.td-total` は `!important` 付きなので背景 `#E8F7B8` がダークモードでも残り、widgets の `td{color:#CCD6E5}` と組み合わさると**コントラスト比 1.29:1** になる。現状は未使用のため実害なしだが、**将来この class を使った瞬間に読めなくなる時限爆弾**である
