# 本番反映確認と、そこで見つかった更新日の不整合73件（2026年7月29日）

## 1. きっかけ：本番を実際に開いて確認した

本日の変更が本当に反映されているかを、`study-quest.net` の実ページで確認した。`boki2-net-test.html` を開いた結果は以下のとおり。

| 項目 | 結果 |
|---|---|
| title（新） | ✅「簿記2級ネット試験の時間配分と解く順番｜90分で合格する問題構成ガイド」 |
| description（新） | ✅ 反映済み |
| 冒頭の役割案内ボックス | ✅ 表示され、cbt-vs-paper へのリンクも機能 |
| **本文の「更新日」** | ❌ **2026年6月30日のまま** |

**JSON-LD の `dateModified` は 2026-07-29 に更新されているのに、画面に出ている更新日は6月30日だった。**

## 2. 全記事を調べたら73ファイルで不一致だった

| 原因 | 件数の目安 |
|---|---|
| **本日のペルソナ一括修正**（`dateModified` のみ44ファイル更新） | 大半 |
| 7月上旬の一括処理の積み残し | 数件 |

放置期間が長いものもあった。

```
toeic-900.html        JSON-LD 2026-06-26 ≠ 表示 2026年5月24日   （1か月以上ズレたまま）
fp3-daigakusei.html   JSON-LD 2026-07-10 ≠ 表示 2026年5月1日    （2か月以上）
cpa-yobikou.html      JSON-LD 2026-07-29 ≠ 表示 2026年4月30日   （3か月）
```

**一括更新をやるたびに不一致が積み増されていた。** 今日が初めてではなく、7月上旬にも同じことをやっていた。

---

## 3. なぜ問題か

構造化データが「7月29日に更新した」と主張し、同じページの本文が「6月30日が最終更新」と表示している。**検索エンジンに矛盾した情報を渡している状態**であり、読者から見ても、記事の鮮度がどちらなのか分からない。

「クロール済み - インデックス未登録」の原因を追っている最中に、自分でこの種の不整合を作っていたことになる。

---

## 4. 対応

- 73ファイルすべてで、本文表示の更新日を JSON-LD の `dateModified` に同期した（JSON-LD 側が実際の編集履歴を正しく反映しているため、そちらを正とした）
- 同期後の再検証で不一致 **0件**
- あわせて `datePublished > dateModified` の逆転がないかも確認 → 該当なし
- `CLAUDE.md` に「更新日を変更するときのルール（必須）」を新設。**一括スクリプトで `dateModified` を触るときは、同じスクリプトで本文表示側も書き換える**ことを明文化した

## 5. CEO所見

**本番を開かなければ、この73件は見つかっていなかった。**

今日は「実行した」「検証した」と何度も報告してきたが、その検証はすべて**ローカルのファイルに対するもの**だった。JSON-LDがパースできるか、divのbalanceが取れているか、置換が当たったか——どれもファイル内部の整合性チェックでしかない。**画面に何が出ているかは一度も見ていなかった。**

`llms.txt` が `.gitignore` に飲まれて本番に存在しなかった件と、構造は同じである。あのときも「実行完了」と報告した後で、本番を fetch して初めて気づいた。**同じ教訓を今日2回もらっている。**

作業のたびに全ページを目視するのは現実的ではないが、**一括変更をしたら、そのうち1本を本番で開く**——これくらいはコストゼロでできる。今日はそれを最後の最後までやらなかった。

なお、73件の日付をすべて 7/29 等に揃えたことについて。ペルソナ修正は著者情報の事実誤りを直したもので、**実際に本文が変わっている**以上、更新日を進めるのは正当である。中身を変えずに日付だけ新しくする行為とは異なる。
