## 6. `boki3-genka.html` — 図解と本文で桁が1,000倍違っていた

### 何が起きていたか

| | 取得原価 | 残存価額 | 年間減価償却費 |
|---|---|---|---|
| **図解SVG** | ¥1,000,000 | ¥100,000 | ¥180,000 |
| **本文の例題** | ¥1,000 | 取得原価の10% | ¥180 |

**同じ記事の図解と最初の例題で、桁が1,000倍違っていた。** 読者は図と本文を突き合わせられない。

### どちらを直したか

**図解を本文に合わせて1/1000にスケールした。** 理由は2つ。

1. 本記事の他の例題も小さい数字で統一されている（逆算問題の累計額¥2,700、売却問題の取得原価¥900）。**図解のほうが唯一の外れ値だった**
2. SVG内の棒グラフのラベルが既に `¥1,000 / ¥820 / ¥640 / ¥460 / ¥280 / ¥100` という**千円単位の表記になっていた。** スケールを合わせると、この既存ラベルと完全に一致する

```
(1,000 − 100) ÷ 5 = 180
帳簿価額の推移： 1,000 → 820 → 640 → 460 → 280 → 100  ✅ 既存ラベルと一致
2年後累計 180 × 2 = 360 ／ 帳簿価額 1,000 − 360 = 640  ✅
```

PC版・モバイル版の両SVGと、本文の figcaption を修正。**6桁以上の数値の残存は両ファイルとも0件。**

### あわせて：同一記事内で年間償却費が2つあった問題

冒頭の概念説明（なぜ一括費用計上ではダメか）が「**1,000円**のトラック・5年・毎年**200円**」、後段の例題が「**¥1,000**・残存10%・5年・**180円**」。

**同じ「1,000円の資産・5年」に対して200円と180円が数十行の間に並んでいた。** 概念説明のほうは残存価額を導入する前の説明であり単体としては誤りではないが、読者にその区別はつかない。

**→ 概念説明の金額を500円（÷5年＝毎年100円）に変更し、数字の衝突を解消した。** あわせて「残存価額0の場合」と明記した。

```
概念説明： 500 ÷ 5 = 100     （残存価額0）
例題　　： (1,000 − 100) ÷ 5 = 180  （残存価額10%）
```

# 追記3：ライトモードが壊れていた件（A-2）を是正（2026年8月5日）

**CEOの見落とし。** `20260804-記事品質改善_creditの貸借逆転とwidgetsのライトモード潰れ.md` は稟議書名のとおり**2件の指摘**だったが、本日はA-1（貸借逆転）だけを直してA-2を放置していた。稟議自身が「**A-2は既定表示（ライトモード）を壊しているため、他の指摘より優先する**」と書いていた。

## 何が起きていたか

`article-widgets.js` のカンマ区切りセレクタ6箇所で、2つ目のセレクタにテーマ限定が付いていなかった。

```css
/* 修正前 */
html[data-theme="dark"] .hc-row.hc-total .hc-label,.hc-row.hc-total .hc-amt{color:#C4B5FD !important;}
                                                   ^^^^^^^^^^^^^^^^^^^^^^^
                                                   テーマ限定なし → 常時適用
```

CSSのセレクタリストは各セレクタが独立して評価される（W3C Selectors Level 3）。左側の `html[data-theme="dark"]` は右側に引き継がれない。**仕様どおりの挙動であり、ブラウザ差はない。**

結果、**ダークモード用の淡い文字色が、ライトモードの淡い背景の上に `!important` で強制されていた。**

| 記事 | 箇所 | 実測コントラスト比 | 本来の色での比 |
|---|---|---|---|
| `boki3-kabushiki.html` | 利益準備金 | **1.43:1** | #15803D |
| `boki3-kabushiki.html` | 繰越利益剰余金 | **1.55:1** | 7.57:1 |
| `boki3-kabushiki.html` | 未払配当金 | **1.59:1** | #1D4ED8 |
| `boki3-shohi.html` | 未払消費税 | **1.43:1** | 4.85:1 |
| `boki3-shohi.html` | 仮払消費税 | **1.59:1** | #1D4ED8 |
| `boki3-shohi.html` | 仮受消費税 | **2.28:1** | #B91C1C |

WCAG 2.1 レベルAAの本文基準は 4.5:1。**1.43:1 は事実上見えない。**

**しかも潰れていたのは金額欄である。** 配当計算・消費税計算の記事で、いちばん読ませたい数字が、既定表示で読めなかった。

## 直した内容

6箇所すべての2つ目のセレクタに `html[data-theme="dark"]` を付与した。

```css
/* 修正後 */
html[data-theme="dark"] .hc-row.hc-total .hc-label,html[data-theme="dark"] .hc-row.hc-total .hc-amt{...}
```

`article-widgets.js` 全体を機械的に走査し、**テーマ限定が外れたカンマ区切りセレクタの残存は0件。** Node の構文チェックも通過。

## CEOの所見

**稟議書のタイトルに「と」が入っていたら、指摘は2件ある。** 今日それを読み飛ばした。

しかもこの見落としは、**本日6回目の同種の失敗**（万円表記／横スクロールのコード未読／1カテゴリからの一般化／`.related-card` の誤特定／完了済み作業を未完了と報告／稟議の2件目を読み飛ばし）である。

対策として、記事修正に着手する前に「**その稟議に指摘はいくつあるか**」を数えて宣言することを自分の手順に入れる。
