## ③ 表示バグ（コードから判定できる範囲）

### 🔴 重大：`boki3-shisanhyo.html` — ダークモードで試算表の金額が読めない

**症状（コードから確定的に導ける）：**

記事ローカルの `<style>` は `html[data-theme="dark"]` の記述を**1つも持たない**。そのうえで金額セルにこう書いている。

```css
.shisan-table td.gokei-kari{background:#F7FCFF;color:#1A202C;}   /* 詳細度 (0,2,1) */
.shisan-table td.zandaka-kari{background:#FAFFFA;color:#1A202C;} /* 詳細度 (0,2,1) */
```

一方 `article-widgets.js` はダークモードでこう当てる。

```css
html[data-theme="dark"] tr:nth-child(even) td{background:#111827;}  /* 詳細度 (0,2,3) → 勝つ */
html[data-theme="dark"] td{color:#CCD6E5;}                          /* 詳細度 (0,1,2) → 負ける */
```

**結果：偶数行だけ背景が `#111827` に変わり、文字色は `#1A202C` のまま残る。**

| 組み合わせ | コントラスト比 | WCAG AA（4.5:1）|
|---|---|---|
| 偶数行 `#111827` × `#1A202C` | **1.09 : 1** | ❌ 大幅未達 |
| 奇数行 `#F7FCFF` × `#1A202C` | 15.79 : 1 | ✅ |

奇数行は読めて偶数行は読めない**縞状の可読性崩壊**になる。潰れるのは装飾ではなく**合計欄・残高欄の金額そのもの**であり、この記事の存在理由にあたる部分。

### 🔴 重大：`boki3-nikkei.html` — ダークモードで仕訳日計表の金額が読めない

同じく `html[data-theme="dark"]` の記述ゼロ。ただし壊れ方が**逆**になる。

```css
.nikkei-table td.n-kari{background:#F7FCFF;}   /* colorの指定が無い */
.nikkei-table td.n-kashi{background:#FFFCF7;}
```

`color` を指定していないため widgets の `html[data-theme="dark"] td{color:#CCD6E5}` がそのまま当たり、**背景は白いまま・文字は明るいグレー**になる。

| 組み合わせ | コントラスト比 | WCAG AA |
|---|---|---|
| 奇数行 `#F7FCFF` × `#CCD6E5` | **1.42 : 1** | ❌ 大幅未達 |
| 奇数行 `#FFFCF7` × `#CCD6E5` | **1.43 : 1** | ❌ 大幅未達 |
| 偶数行（widgetsが背景も上書き） | ✅ | ✅ |

**shisanhyo とは逆に、奇数行が読めない。**

### この2件は2026-08-04の検出と同型だが、原因は別

08-04に検出した `boki3-kabushiki.html` / `boki3-shohi.html` のコントラスト1.43:1は **`article-widgets.js` 側のセレクタ欠陥**が原因だった。今回の2件は **記事側にダークモード対応が存在しない**のが原因である。**共有ファイルを直しても今回の2件は直らない。** 別件として扱う必要がある。

なお `#F7FCFF` × `#CCD6E5` ＝ 1.42:1 と、08-04の 1.43:1 がほぼ同値なのは偶然ではない。**「白背景ハードコード ＋ dark未対応」という同じ制作パターンから出ている。** 同型の記事が他にもある可能性が高い。
