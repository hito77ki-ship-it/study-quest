# 次優先順位棚卸し

**確認日：** 2026-08-11  
**担当：** CEO ジョブズ  
**目的：** 追加施策を増やす前に、AdSense・検索流入・ユーザー体験・事故防止への効果が大きい順に残件を整理する。

## 結論

現時点で最優先なのは、新しい記事や新しいSEO機能を増やすことではない。ローカルに残っている承認済み修正を安全に本番へ反映できる状態にし、AdSenseの「有用性の低いコンテンツ」対策と事実精度の確認を、表示・クリックデータに基づく小ロットで進めることである。

## 監査結果

- ルート直下のHTML、sitemap、内部リンク、JSON-LDを機械確認した範囲では、実在する静的リンクの404、sitemap内の存在しない記事、JSON-LD構文エラーは確認されなかった。
- 動的JavaScript内のテンプレート文字列を静的スキャナがリンク切れと誤検出していた。これは実リンクの問題として扱わない。
- `llms.txt` はローカル作業ツリーに主要記事の追加が反映済み。`robots.txt` の基本方針も `admin.html` 以外を許可する形で大きな問題はない。残課題は本番反映の確認である。
- 作業ツリーには多数の変更が残っているため、全ファイルをまとめて公開するのは危険。公開対象を選別し、検証後に反映する必要がある。
- GSCで確認したプロパティがGitHub PagesのURLで、正規URLの `https://study-quest.net/` と一致していない。GSCとGA4の突合値は、同一ホストでの確認が完了するまで方向性の判断として扱う。
- 定型的な「いいねボタン」表現は現在も183ファイルに残る。これは全件一括削除ではなく、表示回数が多くクリックが少ない記事から、記事固有の学習診断・次の行動へ置き換える。

## 優先順位

| 優先 | 対応 | 判断 | 次の作業 |
|---|---|---|---|
| P0 | 本番反映ゲート | 最優先 | 変更一覧を公開単位に分け、JSON-LD・リンク・画像・表示を確認してから反映 |
| P1 | AdSense残件 | 高 | 承認済み広告除去ロットを完了。`fp3-nannichi.html` は今回対応済み。定型文はデータ順に小ロット化 |
| P1 | 事実精度 | 高 | `toefl.html`、`fp3.html`、`gaibuin.html`、`fp.html`、基本情報技術者の矛盾を公式情報で確認し、必要なものだけ修正 |
| P1 | GSC計測条件 | 高 | `study-quest.net` と一致するGSCプロパティで再確認。現状のGSC×GA4比較は参考値として保存 |
| P2 | 内部リンク・孤立記事 | 中 | ローカル機械監査は問題なし。本番サイトで代表ハブ・関連記事・アプリ導線を目視確認 |
| P2 | sitemap・llms.txt・robots.txt | 中 | ローカル内容は概ね整備済み。本番反映後に取得確認 |
| P3 | 新規記事・追加画像 | 後回し | AdSense再審査の土台が整うまで増やさない |

## 今回の実行

- `fp3-nannichi.html` に残っていたAdSense読み込みタグを削除した。
- 静的HTMLの内部リンク、sitemap実在性、JSON-LD構文を再確認した。
- 新しい施策を増やす前提ではなく、既存の承認済み稟議と本番反映待ちを優先する方針を確定した。

## 次回の実行単位

1. 公開候補を「技術基盤」「代表記事」「事実修正」「広告除去」に分ける。
2. 各候補を変更前後の差分、リンク、画像、JSON-LD、更新日の3面で確認する。
3. 本番反映後にトップページと代表記事を目視し、正規URLのGSCで再クロールを依頼する。
4. 反映後のGSC・GA4を同じ期間、同じホスト条件で比較する。

**CEO所見：** いま必要なのは施策の数ではなく、公開品質を守る仕組みである。検索順位を追う前に、読者が正確な記事へ到達し、読み終えた後に次の学習行動へ進める状態を完成させる。
