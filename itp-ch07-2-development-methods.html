ITパスポート 7-2 ソフトウェア開発管理技術

図書館の予約機能を例に、クラスとオブジェクト、開発モデル、アジャイル・スクラム・XP、DevOpsとMLOpsを学びます。

予約を「データと操作を持つもの」として考える

大学図書館にグループ学習室の予約を追加します。オブジェクト指向では、予約番号や人数などのデータと、予約・取消などの操作をまとめて考えます。共通の定義がクラス、その定義から作られた個々の予約がオブジェクトです。

カプセル化の例は、予約の状態を外から直接書き換えず、取消操作を通して状態を変える設計です。継承では、あるクラスの定義をもとに特性を引き継いだクラスを作れます。UMLは設計を表す記法で、クラス図は構造、ユースケース図は利用者とシステムの利用目的の関係を表す例です。

構造化手法では、予約処理を「空き確認」「登録」「通知」などへ分け、機能やデータの流れを整理します。データ中心アプローチ（DOA）では利用者・部屋・予約といったデータの関係から考え、プロセス中心アプローチ（POA）では申請から受付までの流れを起点に考えます。前章のE-R図とDFDも見返せます。 第6章の図を見比べる

開発モデルは、どこで不確かさを減らすかで見分ける

予約ルールが明確で工程の成果物を順に確認するなら、ウォーターフォールモデルの考え方が使えます。職員が望む画面がまだ曖昧なら、プロトタイピングで先に試作を見せ、要望を具体化できます。スパイラルモデルでは、同時予約などのリスクを見積もり、確認と開発を繰り返します。RADはツールや部品の活用などで短期間の開発を目指します。

設計資料が残っていない旧システムのコードや動きを調べ、仕様や構造を明らかにするのはリバースエンジニアリングの例です。新規機能をどう作るかに加え、引き継ぐものを理解する作業も必要になります。

アジャイルでは、使える単位で反応を確かめる

学習室の空き確認と予約を先に小さく作り、職員の反応を見ます。「キャンセルが電話に集中する」と分かったら、次に作る内容の優先順位を見直します。アジャイル開発では、価値を届けながら変化に適応し、開発の進め方も定期的に振り返ります。

スクラムの役割とイベントを結び付ける

スクラムはアジャイルの考え方を実践できる枠組みです。プロダクトオーナーは価値を最大化する責任を持ち、プロダクトバックログの順序などを管理します。開発者は使える成果を作る作業を計画・実行します。スクラムマスターはスクラムが理解され実践されるよう、チームや組織を支援します。スプリントは1か月以内の固定長の期間です。

プロダクトバックログは製品を改善する作業の順序付きリストです。スプリントバックログには、その期間の目標、選んだ作業、実行計画が入ります。インクリメントは完成の定義を満たす、使える成果の積み重ねです。

XPは、コードを作る実践と結び付けて覚える

XP（エクストリームプログラミング）で扱う実践には、2人で協力してコードを書くペアプログラミングや、先にテストを書き、通るように実装するテスト駆動開発があります。変更をこまめに統合し自動テストで確かめるCI（継続的インテグレーション）も、問題を早く見つけるのに使えます。

開発と運用をつなぎ、利用後の変化を調べる

DevOpsでは、開発担当と運用担当が協力し、変更の統合、テスト、配布、運用の観測をつなぎます。例えば取消機能を追加した後、失敗率が上がったと分かれば、ログを共有して改善します。MLOpsでは、空室を予測するモデルなどを対象に、学習データやモデルの版、評価、運用中の性能を管理します。実際の利用傾向が変わったら、原因を調べ、再学習や更新の必要性を判断します。

共通フレームはシステムのライフサイクルの作業を関係者が共通に理解するための整理です。CMMIは組織のプロセスの改善に使われるモデルです。どの手法を使うかという話と、組織の仕事の進め方をどう改善するかという話を区別します。

解説つきの自作例題6問

まず自分で選び、解答を開いて、判断に使った条件を確かめます。

第1問　ひな型と実際の予約

予約番号・人数・取消操作を定めたひな型と、そのひな型から登録された予約R01の組合せはどれですか。

  1. R01がクラス、ひな型がオブジェクト
  2. ひな型もR01もクラス
  3. ひな型がクラス、R01がオブジェクト
  4. ひな型がユースケース、R01が継承
第1問の解答と解説

ウ　ひな型がクラス、R01がオブジェクト

クラスは共通の定義、オブジェクトは具体的に作られた一件です。同じクラスから人数や予約番号が異なる予約を作れます。

第2問　試作を使って要望を確かめる

職員の希望がまだ曖昧なので、まず操作できる画面案を見せ、どのボタンが必要かを確かめます。最も直接当てはまるのはどれですか。

  1. プロトタイピング
  2. リバースエンジニアリング
  3. 運用テスト
  4. ホワイトボックステスト
第2問の解答と解説

ア　プロトタイピング

早い段階で試作品を使い、要望を具体化する例です。旧システムの仕組みを調べて構造を明らかにする作業はリバースエンジニアリングです。

第3問　反応を次の開発に生かす

予約機能を使った職員から、電話による取消が負担という声が出ました。アジャイルの進め方として適切なのはどれですか。

  1. 最初の予定を守るため意見を保留する
  2. 完成品をすべて提供するまで反応を集めない
  3. 動作確認を省いて全変更を一度に入れる
  4. 使われ方を確認し、次に作る内容の優先順位を見直す
第3問の解答と解説

エ　使われ方を確認し、次に作る内容の優先順位を見直す

動くものから学び、次の優先順位を見直します。例えば取消を先に作り、職員の手順に合うか再度確かめます。

第4問　スクラムで振り返る内容

完成した取消機能を職員と確認した後、チームは検証が遅れた原因と次回の改善策を話し合います。後者のイベントはどれですか。

  1. スプリントレビュー
  2. スプリントレトロスペクティブ
  3. スプリントプランニング
  4. デイリースクラム
第4問の解答と解説

イ　スプリントレトロスペクティブ

成果と次の方向を関係者と確認するのはレビューです。チームの仕事の進め方を点検し、次に改善する方法を考えるのはレトロスペクティブです。

第5問　テストから実装を始める

先に「5人を拒否する」テストを書き、失敗を確認してから必要なコードを実装します。何の例ですか。

  1. 受入れテストのみ
  2. 類推見積法
  3. テスト駆動開発
  4. 運用監視
第5問の解答と解説

ウ　テスト駆動開発

先にテストで期待する振る舞いを表し、それが通るように実装します。通った後に振る舞いを保って内部を整理し、同じテストを実行します。

第6問　空室予測の精度を追う

予約アプリに空室予測を追加しました。運用中に予測精度が落ちたため、学習データ、モデルの版、評価結果を調べます。特に関連するのはどれですか。

  1. MLOps
  2. ホスティング
  3. 回帰テストだけ
  4. クラスの継承
第6問の解答と解説

ア　MLOps

モデルとデータを含めて運用するMLOpsの例です。原因や新しいモデルの評価を確かめてから、更新の要否を判断します。
